## 0. Standing rules

### Live parallel operator view

The graph has one dependency order and several concurrent workstreams. A machine is an execution host, not a scientific node: Studio remains the durable data owner, while an available interactive host coordinates science and deliverables. The live sidecar shows every active workstream separately, including its owner, node, exact object, input generation, last heartbeat, next join and blocker. A single `NOW` label is incomplete whenever more than one workstream is active.

Every work package uses the current contract in `docs/research-requirements.md` and the acceptance list in `docs/research-node-checklists.md`. The registry consolidates the accumulated session requirements, and the checklists carry them into the node brief; a worker cannot close a paper, deck, methods or data sweep by repairing only the latest example.

Logical workstreams may share a host, and not every workstream needs a live agent. Parallelism is used when inputs and write ownership are disjoint. CPU headroom by itself is not a reason to create another writer or fit another specification.

**Default lane scheduler.** The coordinator fills safe lanes without waiting for Java to request parallelism. On an interactive executor with four reasoning slots, the standing allocation is one coordinator plus three workers: science/methods, paper, and deck. Studio's durable data worker is separate, so the normal project state has five concurrent lanes: Studio data; interactive coordination and live scientific debate; science/methods; paper; and deck. Studio monitoring, git-status polling, resource checks and clean-boundary synchronization belong to the coordinator and do not occupy a reasoning slot unless a bounded diagnosis genuinely requires one. A read-only reviewer temporarily replaces the builder whose completed packet it reviews; it does not displace an unrelated active lane. When a worker finishes or reaches a real dependency, the coordinator immediately assigns the next ready package from the graph. An idle slot must name the file conflict, invalid input, resource limit or dependency that leaves no safe package ready.

The priority order for a newly free lane is: (1) a scientific probe, rival test or methodology sweep that can change the paper's answer; (2) a paper or deck change consuming an existing finding; (3) repository or workflow maintenance required by an active package. A new interjection reroutes only the affected package, while compatible work continues. Two writers never share a mutable file or generated artifact. Heavy scans remain limited by the host's measured CPU, memory and I/O preflight; reasoning, writing and small-panel estimation may continue while one heavy Studio build runs. A departure from this allocation is recorded before execution with the reason, displaced package and condition for restoring the default. This makes serial execution a justified exception rather than the silent fallback.

**Every deck touch runs the same deliverable loop.** Review the source diff and its scientific consequence; run focused producer/unit tests; compile `deck/main.pdf` locally on `main`; run evidence, vocabulary and source-only status/provenance audits; render and inspect every changed page against the prior PDF; then commit only if the whole deck remains ready to present. A large scientific change also reruns every dependent figure/table owner. Provisional status, source paths and commit identities live in source comments or manifests, not in rendered slides. Page count is diagnostic, not a success criterion.

**Prior corrections are an executable preflight, not conversational memory.** Before data, analysis, deck, or prose work, run `./scripts/run scripts/research_action_preflight.py <action>` and state the purpose-bound estimand, exact evidence generation, and prior correction the planned action could reverse. Search the canonical workflow, claim registry, recent ledger and repository before adding an object: amend the existing owner, merge the useful content, remove or explicitly supersede stale duplicates, and create something new only when no current object can carry the work. The printed checks cover economic materiality before remediation, calendar time versus design, fixed comparison sets, distinct appearance/substitution/persistence/hysteresis objects, the persistent visual backlog, and direct raw-passage prose imitation. A fresh worker changes its plan when it conflicts with one of those checks; it does not rely on Java to notice the regression later. Interjections that establish a reusable correction are promoted into this preflight or the relevant canonical node before the current iteration closes. New scientific discoveries and genuinely unresolved choices remain conversational so Java can debate them live.

**High effort is bounded scientific judgement, not perfection chasing.** Classify an objection before spending on it. Wrong identity or arithmetic, impossible timing, an undefined estimand, and invalid inference are hard failures. A data or design concern blocks only when a purpose-bound bound shows it can plausibly change the sample, sign, economic magnitude, mechanism or inference. A residual alternative that changes interpretation but not validity travels beside the strongest published-field-calibrated claim as scope or caveat. Engineering and presentation debt stays in its own backlog and never rewinds a scientific node. One builder pass, one independent challenge and, when claim ambition is at issue, one direct comparison with raw published-paper passages complete a normal review round; the integrator must then promote, narrow, park or reject. Another round requires a new material contradiction, not a more elaborate restatement of uncertainty. No second consecutive iteration may deliver only a certificate or workflow refinement unless the first exposed a claim-changing defect or a hard failure. Every other iteration advances a scientific object—claim, estimand, exhibit, rival test, interpretation, deck frame or paper section.

**A no-fetch result is a certification, not an inventory status.** The executable stage must reopen the current thin-consumer audit, every cited certificate and every installed raw stat identity under the canonical raw-generation mutation lease, bind both the audit digest and the closed consumer-registry identity into its prelaunch forecast, and return a distinct inventory-only status when that certification is unavailable. The forecast carries the exact registry-derived acquisition perimeter and budget. When that perimeter is empty, the stage exposes no acquisition command; adding a stream requires a reviewed executor and measured budget in the same generation. A whole-schema engineering scenario remains diagnostic and must never be reported as installed storage or an authorized project requirement.

**Portability.** This file and every node's output is a plain tracked file in this repo. No node's real state may live only inside one model's session. Whatever executes a node reads this file plus the previous node's committed output and continues.

**Git checkpoints are the durable executor handoff.** Commit and push every coherent, tested node boundary to `main`, and always do so before an executor or provider switch; do not leave accepted work only on an agent branch, worktree, temporary directory or one machine. During continuous work, create a safe pushed checkpoint at least once per working day and sooner whenever a review closes, a release is certified, a finding packet becomes reproducible or a deliverable builds cleanly. After each push, fast-forward every active clean checkout on the other research machine and verify that its `HEAD` equals `origin/main`; a dirty or running checkout is never force-updated, and its immutable job inputs and restart markers remain in place until the job finishes. Experimental branches may exist while independently reviewed, but accepted branches are merged promptly and superseded branches and worktrees are audited and retired. A provider switch resumes from the latest pushed `main` SHA plus durable runtime markers, never from conversational memory.

**One runner owns the research environment.** Invoke scripts and tests through `./scripts/run`; individual entry points never mutate `sys.path`. The runner places the current worktree's `src` and repository root on the import path, suppresses script-directory shadowing, and may reuse the primary checkout's environment without importing its source. Reusable logic still belongs in `src/ddvc/`, while `scripts/` remains thin entry points. This is a correctness gate, not only style: an editable environment shared with a linked worktree otherwise imports the primary checkout silently and can validate code other than the code under review.

**Logical data identity survives worktrees.** Provenance and cache keys record the repository-relative lexical input path, even when that path is a symlink to a shared data tree; the fingerprint still traverses and identifies the target contents. Resolving the symlink target into an absolute host path makes identical inputs look different across linked worktrees, destroys valid resumable caches at merge time and writes machine-specific manifests. A generated cache may move to the corrected logical key only after its marker, schema, row-count and deterministic-sample contracts pass.

**Engine, cache and result fingerprints depend on semantics, not orchestration.** Source-record meanings live in one small dependency-free module. Fetch cadence, retries, metadata writing, command help, release-gate implementation and documentation do not own those meanings and are excluded from analytical result fingerprints. A code change invalidates a materialised engine, day cache or panel only when it can change its rows or quality contract. The release gate remains an executable precondition for every consumer but is not itself an input to the consumer's economic result. The global market-state ledger is the exception because its cross-venue causal-order audit is an output column, so that audit code is part of the ledger's provenance without entering the partition engine key. These boundaries are tested explicitly; tying an expensive transform to orchestration makes harmless operational edits trigger full rebuilds and is a provenance defect, not conservatism. When an old exact-byte cache key differs only because comments, formatting or docstrings changed, the refresh owner may create a relative alias to the recorded release only after the provenance verifier reconstructs the stamped bytes and proves semantic and input identity. It never copies the cache, replaces an existing path, aliases an executable change or restamps old output as new.

**Compactness is a release invariant.** Before materialising a large analytical state, forecast both the unavoidable first-copy bytes and the incremental physical bytes of the proposed generation. One immutable partition has one physical owner; release manifests bind its hash and provenance without copying it. A new generation reuses unchanged partitions only after source, producer and input identity reopen, using content addressing or filesystem clone semantics where the platform supports them. Producer fingerprints are family-scoped, so a change confined to one protocol family cannot fork unrelated state. Cleanup is reachability-based: retain active releases and explicit pins, then report the exact unreferenced generation directories and their logical bytes before any sweep. A build that cannot state these bounds has not passed its storage gate.

**An additive schema migration is a checked transform, not a claimed shortcut.** A prior canonical partition may seed a new engine only when its raw-input fingerprint still matches, the old schema version is exact, and the migration leaves every pre-existing economic field unchanged. The migration writes the new schema through the same atomic boundary, recomputes affected quality counts, and then compares early, middle, and late migrated days for every venue against fresh raw normalization with exact field values and exact quality markers. A changed amount, identity, timing rule, invariant, filter, or row interpretation requires raw rematerialization; migration is allowed only for newly explicit metadata whose value is fully determined by the already canonical row. The full independently generated calendar and provenance ledger still run after migration.

**Provenance rebinding requires complete equivalence, not representative validation.** A stratified or random sample can validate transformation logic, but it cannot authorize rebinding every preserved partition to a new input fingerprint or engine. Such a migration must prove semantic equality on every rebound partition or establish a complete mechanical identity proof over every old and current input. One unsampled difference invalidates the whole rebind. Publication retains its journal and backups until rollback or promotion has been reopened and verified; rollback failure must preserve recovery evidence. Concurrent readers either acquire the same release lease or observe one atomic release identity, never a marker-first, ledger-last mixture.

**Raw provider data stops at node D.** Raw JSONL is an immutable ingestion layer, not an empirical interface. Node D versions the released source manifest, canonical meanings, integrity evidence and purpose-bound research inputs for each AMM family: directed swap legs and identities; constant-product closing inventories or exact target states; concentrated-liquidity signed state changes, replay checkpoints and exact target states; StableSwap pool snapshots and calibration trades; and weighted-pool closing balances plus ordered swap/join/exit events. Source-specific aliases and schema variants are resolved once through the canonical family reader. They need not be copied into a second event-for-event table merely to become canonical. A full normalized event-state cache is an optional rebuildable accelerator, never a release prerequisite, unless a named estimand actually consumes every row. Every materialised partition carries an explicit schema version, row and identity counts, causal-order coverage, duplicate/conflict counts, unsupported-state reasons, and an input-aware fingerprint. Canonical readers exclude `usable = false` rows by default; an audit must opt in to see quarantined rows. A partition passes when no incompatible payloads claim the same causal identity, not when support is 100%: missing snapshots, incomplete provider entities, nonstandard token mechanics and impossible states remain counted, quarantined and visible in the coverage ledger. Each experiment then registers the support population and diagnostics required for its estimand on top of the canonical integrity gate. Data remediation is outcome-materiality-based: first bound a defect by economic weight and its concentration across time, venues, entities, treatment or mechanism cells and stress states; repair it only when it can plausibly change a headline measure, sample composition, coefficient or inference. A diffuse immaterial gap remains in the exclusion and coverage ledger and receives a conservative sensitivity bound when useful; it does not hold the graph at D merely because coverage is below 100%. The integrity and coverage gates for the registered support perimeter must clear before E locks that design or F runs that experiment. A full-calendar gate applies only when the estimand itself uses the full calendar. Downstream estimators, validators and quote builders consume only released canonical readers or purpose-bound products. Reading provider rows outside that boundary is allowed only for an ingestion audit or a named defect diagnosis, and such output is diagnostic evidence, never a finding. A new provider schema or missing field reopens D instead of growing another local parser inside an experiment.

**Purpose-bound products derive directly from certified streams.** The released raw certificate plus the ordered semantic normalizer form the canonical event interface. D3 signs integrity and support over the exact registered perimeter while streaming into the narrow panel named by an estimand; a compatibility or full event-state cache is not canonical authority, and deposited-capital, V2-rent and transaction-frontier builders do not depend on it. Every purpose-bound release binds the raw certificate, correction generation, semantic producer, exact calendar, integrity and support counts and output hashes. Before materialisation, the builder forecasts incremental physical bytes and refuses repeated venue, day, family, token, event or post-state fields unless a registered consumer needs that representation. Unchanged content is reused only after its identity reopens, and unreachable generations enter the cleanup report. Replay derives ordered state directly from certified event streams and persists only the minimal checkpoints required for exact resumption.

**Node D closes one purpose-bound contract before its experiment begins.** D has three internal gates. D1 inspects the live provider schema and real partitions for the sources, fields and bounded child identities required by the named estimand, classifies nested relationships that would multiply rows, and compares that purpose-bound subset with the entered claim and its active consumers before an expensive fetch starts. The fetch contract includes every admitted field in one pass; a consciously excluded field carries a typed reason, so later work cannot rediscover the same omission as an ad hoc backfill. D1 then fixes each admitted field's canonical meaning and freezes the family schemas. D2 certifies the exact registered window and support needed by the estimand. A full-history or full-calendar claim uses the entire locked research window; a fixed-date construction or mechanism test certifies its predeclared dates. An audit subset may exercise the code but never become a different estimation sample by convenience. Certification does not require an event-for-event derived copy. Each purpose-bound materializer declares the smallest sufficient output grain before launch: daily closing pool inventory for a deposited-capital estimand, pre-transaction state for registered target routes and candidate pools, signed provider flow for an allocation estimand, or a compact checkpoint for causal replay. The route and quote-state contracts are separate because topology covers eight routed venues while exact counterfactual pricing covers six state-reconstructable venues. The directed-route layer has 2,332 calendar partitions and 12,802 launched venue-days; a day with zero swaps is a typed empty partition, not an absent date. The quote-state coverage ledger has 11,009 family-venue-days, but a wide state row for every event is not the denominator. Before migration or rekey, `fetch_raw_market_data.py coverage --strict` must pass the exact research perimeter; the command rejects a missing file, sidecar, row ledger, mismatched canonical source/filename identity or stale Graph query contract. Each Graph stream sidecar binds the provider-schema snapshot, entity, normalized selected fields, time/date boundary, chunk policy and page size, so a provider schema change or expanded admitted field makes the installed raw file stale and forces one atomic generation backfill, never a sequence of consumer-specific repairs. Rekey independently refuses any absent currently required stream. D3 signs the quality and support ledgers over that registered perimeter, then materialises analysis-ready panels from released canonical iterators, checkpoints and purpose-bound states. Every active D3 builder calls the shared `ddvc.data_release` gate before reading a day: it checks the exact independent perimeter, passing family ledger, semantic engine identity, current raw fingerprint and current per-partition marker. Globbing whatever files happen to exist is not a release condition. Only released analysis panels enter E and F. The transaction-state branch has one explicit validation loop: D3-base builds its prerequisites, E runs a separately named 77-date construction audit, failure returns to D2, and success returns to D3 for the separately named full-daily frontier. The full-daily builder enforces that edge itself: it requires the current audit panel, rejection ledger and support provenance and exact agreement with the current 77-date calendar. The audit reports the full route-error distribution, bias relative to the outcome scale, economic-weight coverage and failure concentration by year, venue, pair and regime. A pooled 99% reproduction share remains a dashboard statistic, never a release rule that can hide an economically selected 1%. After scoring, the daily support ledger independently covers the exact released calendar and repeats those diagnostics before any canonical daily artifact is assembled or stamped; promotion blocks only when the measured error or concentrated missingness can materially create the claimed effect under the registered sensitivity bound. Audit and explicit-date serial replays retain bounded 180-day resumability checkpoints. Full-daily replay first derives ordered causal state and installs immutable checkpoints at each segment's `strictly_before_first_event_of_day` boundary, then assigns disjoint contiguous, work-balanced scoring segments to bounded worker processes. Certified day inputs may be decoded into contiguous temporary shards by bounded workers, but one reducer must still apply those shards in exact calendar and block-log order because tomorrow's state depends on today's close. A restart resumes from the latest validated checkpoint before the first missing boundary and maps only the required suffix; an unchanged restart reuses every validated checkpoint. Each scoring worker preserves exact block-log order within its segment and cannot publish; ordered assembly begins only after every segment certifies complete. The audit never stands in for the daily 1-, 7-, 30-, and 120-day analysis input. A partial family build, a raw-data spot check, or a validator run can send D1 or D2 back for repair, but none releases an estimator. A K proposal that needs a field outside the current contract opens a new purpose-bound D1; it does not retroactively widen a completed contract.

**A long streamed transform holds one exact source lease.** Its cache key includes the resolved release identity, not only code and convenient input paths. The consumer reopens the full certified lineage immediately before and after reading. Checkpoints and day caches stay in a private transaction directory until the second validation passes, then publish marker-last into that same generation. A final validation follows promotion; drift rolls back only the newly promoted cache files. A retry may reuse a complete cache from the same identity, but it may not mix generations or bless work produced while the source changed.

**Audit observability is part of D1, not a post-release reason to rebuild.** Before D2 starts, D1 names the compact exclusion counters or ledgers needed to bound every known unsupported state, specifies their unit and materiality threshold, and makes the canonical transform emit them during its existing pass. After a large generation is certified, a missing convenience field or cleaner audit architecture does not reopen D by itself. Use bounded read-only evidence to form a conservative materiality ceiling; rebuild only when that ceiling can change a registered sample, estimand, coefficient or inference, and schedule the architectural improvement for the next planned generation otherwise. Never install a second normalization, deduplication, repricing or state-replay path merely to avoid that decision.

**Certificates, not apparent maturity, advance the graph.** Every edge consumes a machine-readable certificate that identifies the exact upstream generation, scope, schema, code and inputs. At the D2-to-D3 edge, certification precedes the first scientific read: an audit, experiment or panel builder receives a certified ordered manifest or released generation binding, never a raw glob, file-existence check or caller-assembled list. Its output binds the certificate or ledger, code, static-snapshot and content digests so a changed ancestor invalidates the result before reuse. An existing panel, table, manuscript section, green compile or recent commit does not imply that its node passed. A changed or failed ancestor makes every descendant certificate stale before any descendant runner starts, and a descendant in construction mode may write diagnostics only. Repair resumes from the nearest invalid ancestor and reuses only shards whose own certificates still verify; it does not restart unrelated branches or continue polishing a stale descendant. This is the preflight that must run before an expensive node, not an audit reconstructed after the node has already consumed days.

**Provisional estimates shorten the path to certified findings but never advance the submission graph.** Once an internally coherent D snapshot exists, existing empirical runners may execute against it before the final D release to check plausibility, functional form, support and sensitivity. Each provisional run binds its exact input, code and specification identities. A later run against changed inputs reports which observations and variables changed alongside coefficient, standard-error, sample and diagnostic changes: small input changes should usually imply small output changes; unchanged output after an economically relevant input change triggers a code-or-influence audit; a large result change attributes the earlier estimate to the changed input and reopens the affected design. This lane is useful only when it reuses the current empirical machinery and produces information sooner than waiting; building extra workflow infrastructure that delays the paper fails its own purpose. A reproducible provisional estimate may enter the always-ready working paper or deck at its supportable scope, with its identity and refresh requirement in source comments, and it updates in place when the input changes. It cannot enter the submission certificate or become a locked headline until it is rerun on the released D generation. Retired, contradicted, or presently irreproducible estimates remain excluded from both deliverables.

**Exploration is multidimensional before it is chronological.** E0 cannot default to a monotonic trend or calendar narrative. For each candidate pattern it examines the cross-section, the full outcome and support distributions, composition and a named decomposition, economic topology, and interactions or state dependence; a dimension may be omitted only with a recorded reason that it is undefined or immaterial to the estimand. When separate cuts reveal economically material heterogeneity, the next fitted family estimates a joint-conditioned model on explicit common support, with the relevant interactions, cell support and inference, rather than narrating marginal cuts as independent mechanisms. These lenses are a discovery discipline, not a demand that every result survive or every exhibit carry every dimension. Provisional patterns establish plausibility and choose the next design. They may be discussed in the working paper and deck when reproducible and precisely scoped, but only a distinct rerun on certified D3 inputs with an E1 definition and closed attack set can make them submission-authoritative findings.

**Common support defines a conditional estimand; its share does not grade the result.** A support intersection that retains a small fraction of the parent panel is not weak merely because the fraction is small, and a large retained count does not license population extrapolation. First name the economic population on which both objects are observed, then report its observation, entity, time, venue and regime support and compare included with excluded observations on predetermined observables. Widen and tighten the support and notional rules without changing the estimand. If inference and selection diagnostics are sound, the conditional result may carry main mechanism weight; it remains bounded to that support unless a reweighting, bounding or separate design justifies extrapolation. Never demote a result from its support percentage alone, and never hide economically selected overlap behind a large row count.

**Every gate declares its provenance and consequence before it binds.** A machine-readable gate entry names the estimand and failure mode it protects; classifies itself as mathematical validity, data integrity, project incident control, empirical convention or presentation guidance; cites the exact full-paper and companion location when it claims literature precedent; records any project-data calibration or simulation that selects a number; defines its denominator and strata; states false-pass and false-fail costs; lists sensitivity values; and says whether failure blocks estimation, blocks claim promotion or triggers disclosure only. Mathematical impossibilities, causal-timing violations, identity conflicts and invalid covariance remain hard failures. A number without mathematical necessity, direct venue precedent or project-specific bias calibration is a diagnostic or sensitivity, never an automatic scientific veto. Literature absence does not prohibit a method or measure; it only prevents claiming literature support. Vocabulary is the explicit exception because zero use across a sufficiently broad field corpus is evidence that a term is nonstandard. A changed estimand, data generation or effect scale reopens the gate calibration.

**Venue calibration separates validity from ambition.** Full-text and companion reads of the JFE venue corpus calibrate seven recurring gate classes, and every project gate maps to one before execution. Measurement identity, accounting consistency and mathematically valid inference block estimation because failure makes the object or estimator undefined; this project applies a stronger raw-lineage burden than typical venue papers because its novel on-chain measures are generated rather than externally standardized. Sample overlap and missing support define a conditional estimand and trigger composition, influence and, when the target population warrants it, reweighting or bounds; neither a low share nor the absence of inverse-probability weighting is itself a veto. Timing, exclusion and pretrend failures block causal language, not a correctly labeled descriptive or predictive estimate. Rival tests and robustness target material alternative explanations and known design sensitivities; they do not require closing every conceivable objection, while a sign reversal or economically large rival reopens the claim. Discovery on the same sample cannot promote itself: a new result needs an explicit E1 definition and a distinct rerun or holdout before headline use, a discipline stricter than several published exemplars whose robustness volume exceeds their identification. Economic magnitude, uncertainty and outcome-scale comparison are promotion requirements even when a coefficient is statistically valid. Structure, breadth, appendix allocation and visual polish are presentation gates: they can block paper delivery, never suppress a scientifically valid result, and every limitation that changes interpretation stays visible in the main text. The calibration sources and page-level evidence remain in `docs/literature-audit.md`; the workflow copies the consequence, not a journal paper's particular estimator or arbitrary threshold.

**JFE resemblance includes the scientific package, not only language.** At E0, J1 and J2-paper, compare the project with the closest published empirical papers on the number and hierarchy of economic questions, identifying comparisons, descriptive foundations, mechanism tests, rival explanations, heterogeneity, robustness, economic-magnitude interpretation and appendix support. The comparison names what the published papers actually do and what our data can defensibly do; it does not demand a fixed table count or copy an unrelated estimator. A manuscript can pass prose diagnostics and still fail this benchmark because its evidence is too narrow, shallow or repetitive. Conversely, adding regressions that do not answer distinct economic questions does not increase breadth. Every venue-gap finding must schedule a scientific package, change the paper's ambition, or be marked inapplicable with a reason; a free-standing optics memo is not closure.

**An insignificant estimate is interpreted through its confidence interval, not promoted as zero.** Before reading the sign, compare the interval with a named economically relevant benchmark such as the aggregate change, a sample standard deviation or the mechanism's required scale. If the interval includes zero and economically material effects, report the point estimate as potentially important but imprecise; it may be described as suggestive or consistent with stronger evidence, but it cannot carry the claim. If the interval includes zero while excluding effects large enough to matter for the question, report an informative bounded null and state what magnitude is ruled out. Bolton and Kacperczyk's published Paris exercise follows the first pattern: it calls 3.7–4.5% point estimates fairly large, immediately says they are statistically insignificant, and treats them as broadly consistent with other results while noting low power in noisy returns (`literature/text/2021-BoltonKacperczyk2021CarbonRisk-do-investors-care-about-carbon-risk.txt`, lines 2238–2249 and Table 15). Every main result therefore reports the estimate and standard error or interval together; prose never turns $p>0.05$ alone into evidence of no effect and never turns a large insignificant point estimate alone into evidence of an effect.

**A supported measurement family does not wait for an unsupported sibling family.** When a question names several protocol, venue or quantity families but each has a separable estimand, E0 runs every family whose own quantity, support and provenance contracts are coherent while the others remain gated. The partial-family result names its exact perimeter and cannot stand in for a pooled or cross-family claim. It runs on the supported family's full calendar first, then on economically motivated subsamples and balanced perimeters as sensitivities; a pre-technology sample may reduce architecture mixing but is not presumed better identified because market composition, maturity and support also change. Once the missing sibling family becomes admissible, the graph adds its separate result and only then tests cross-family corroboration.

**Coefficient instability is diagnosed before controls are expanded.** First align the outcome, contrast, sign convention and exact observation support; coefficients from different estimands receive only a conceptual bridge and never share one specification curve. On one unchanged sample, fit an intercept-only support bridge and then add predeclared economic blocks, reporting coefficient movement, support, cluster counts and covariance validity at every step. Predetermined confounders may enter the baseline, while contemporaneous liquidity, routing, volume, gas or reach variables remain mechanism or all-in-outcome objects when the focal comparison can affect them. A variable absorbed by the fixed effects cannot become a useful level control merely by being listed; conditional gaps require estimable interactions or paired differences. Sparse interaction cells fail an explicit support gate, and an invalid covariance remains recorded rather than replaced by a preferred specification. Controls are never selected to recover a desired sign. If well-supported conditional effects differ, heterogeneity is the result; a universal claim requires the relevant conditional effects themselves to retain one sign under the admitted weighting and influence checks.

**Review and discovery overlap; promotion remains serial.** Once a coherent fingerprinted snapshot exists, analysis chunk (n+1) proceeds while chunk (n) is under adversarial review; the whole queue does not wait for each verdict. A fatal or claim-changing finding invalidates the affected artifact and every descendant bound to it, a local defect repairs that branch while independent branches continue, and a bounded immaterial defect enters the support or exclusion ledger with its sensitivity bound. Reviewers may therefore examine one completed chunk while the next probe, decomposition or falsifier runs, but each run has an immutable identity and no two writers share an artifact or lock. Concurrency is bounded by measured CPU, memory, I/O, provider limits and dependency edges, with at most two heavy scan lanes per host unless a scale preflight proves more are faster. Before E1, confirmatory F, the manuscript or the deck can promote a result, that result must be rerun on the current D release and every material review on its ancestry must close. Straight one-shot steps may stay strictly serial; iterative discovery defaults to this overlapping cadence because incomplete support and review-driven revision are part of the design, not reasons to leave compute idle.

**A schema promise is not field availability.** Before an expensive materializer starts, D1 inspects real early, middle and late partitions and records non-null coverage for every load-bearing field. A synthetic fixture proves code behavior only; it cannot establish that a provider actually populated a field. A source field with zero or inadequate corpus coverage is removed from the contract before the build, then replaced by a separately validated canonical transform or left unsupported. The same preflight runs again when a provider generation changes. This rule was added after a V3 LP-flow fixture supplied `amountUSD` although all 5,806,382 real mint/burn rows had token amounts but zero provider USD values.

**A partition validator must accept the canonical generator and the installed corpus before it can reject drift.** Tests derive boundary fixtures from the same single-owner range or calendar generator used by production, including nonaligned first partitions, aligned interiors, truncated terminal partitions and empty members; hand-written neat intervals are not sufficient. When a validator, schema or partition identity changes and installed artifacts already exist, the review runs a read-only production-compatibility smoke before merge and reports expected, present, valid, missing and extra partitions plus the first disagreement. Any newly invalidated perimeter receives an explicit scientific or migration adjudication before refetch or rebuild. A synthetic adversarial certificate can prove rejection behavior, but it cannot establish compatibility with the bytes the pipeline is about to consume. This gate was added after a validator that correctly rejected arbitrary five-block V4 chunks also rejected the real short deployment-to-boundary chunk, which would have mislabeled the entire existing exact-state cache as missing.

**Scale feasibility is a D1 certificate, not something learned halfway through D2.** Before a multi-hour fetch or materialisation starts, its executable preflight probes the exact live query shape on quiet and busy early, middle and late ranges; preserves structured HTTP and RPC failures; records provider range and result caps; inspects the actual schema, event-topic set and completeness marker of every reusable raw generation; and refuses to infer payload coverage from filenames or file counts. It enumerates the full call, row and byte perimeter, forecasts wall time, memory and free-disk demand under bounded concurrency, names the host split and immutable shard boundary, and proves overlapping consumers resolve to one canonical raw key before workers launch. A small pilot may establish these contracts but remains diagnostic. A provider-policy change, unrecognised legacy schema or forecast outside the available resource envelope reopens D1 before scale work begins. This gate was added after a route panel completed 113,822,022 rows against pre-release state lineage, a legacy V3 cache omitted Mint and Swap despite 13,094 plausible filenames, and the live RPC's global-log ceiling forced a cache redesign after acquisition had begun.

**Physical storage is part of the materialisation contract.** Before an expensive transform starts, its preflight reports source bytes, expected logical output bytes, incremental physical bytes after content reuse, peak temporary bytes, bytes per retained scientific row and the largest repeated field families. It must compare a wide universal cache with the smallest purpose-bound output that answers the registered estimand. Repeating an immutable raw event as a second wide state row is not justified by provenance alone. Prefer streaming normalization, compact replay checkpoints, daily closing inventories and exact target-state rows; store identifiers and large integers in compact typed representations when they must persist. Immutable releases reuse byte-identical partitions through verified links or copy-on-write clones, and generation identity changes only when the family's scientific semantics or raw inputs change. A build whose projected physical expansion is dominated by duplicated generations, unused intermediate states or repeated metadata returns to design before launch. Reachability-based cleanup removes superseded unreferenced generations after current pointers, manifests and cross-host copies are verified. This gate was added after five nearly complete event-state generations consumed 527 GiB although one old-layout release was about 90 GiB and the active liquidity and frontier estimands required much thinner outputs.

**Provider rows do not prove event-source completeness.** Every load-bearing event stream must reconcile exact block, transaction and log identities against an independent source on a predeclared calendar before its canonical generation can be released. The comparison covers counts, missing and extra identities, duplicates, event class and exact signed quantities where available; a synthetic fixture, non-null coverage or a successful pagination loop cannot clear it. An observed provider omission first triggers a recorded materiality adjudication. An omission that is load-bearing, economically material or plausibly correlated with the outcome, mechanism, treatment, stress state or sample selection returns D to source repair and requires an independently retrieved supplement for the affected scope. A bounded immaterial omission may instead remain excluded when the release reports its count, economic-weight bound and concentration and does not call the resulting ledger exact or complete. Downstream code never floors an impossible state or silently treats bounded coverage as full coverage. For any factory-deployed pool family, the canonical pool census comes from the factory's complete on-chain creation-event sequence through a frozen upper block, with exact address, factory and creation-parameter validation; a provider's static pool snapshot may enrich that census but may not define it. Every independently retrieved Ethereum log chunk, whether it carries factory identities or economic events, retains the exact RPC request and response, sanitized endpoint and complete attempt history and binds the successful endpoint to a certified frozen terminal header; reuse reopens that evidence and reproduces the stored rows, while a legacy decoded-row cache without the response is quarantined and refetched instead of upgraded by assertion. For V2-family replay, one shared 77-date transaction-frontier calendar now binds Uniswap V2 and Sushi V2 Mint, Burn and Swap streams to independently fetched Ethereum logs with exact UTC block cuts, audited token decimals and zero-event rows. Its pool registry comes from each factory's complete on-chain PairCreated sequence, and each daily core-event fetch is global by topic with no address filter before registered pools are attributed to venues; Graph rows under audit never define their own audit perimeter. The global raw responses live once in marker-last, globally aligned 50-block chunks, matching the current provider's enforced maximum; every log request is issued as a bounded two-item RPC batch with the frozen-upper header on the same successful endpoint, and its exact request, canonicalized response digest, sanitized endpoint and attempt history are revalidated on reuse. Completeness and event-order reconciliation read the same files, complete chunks are immutable, and provenance points to them by portable relative path without copies or hardlinks. The workflow DAG is structural market-state prerelease, audited token decimals, independent V2 certificate, then full market-state release; builders of certificate inputs never call the downstream full-release gate. A current zero-exception certificate is required by both the market-state release and findings-freeze gates, which reopen every cited deployment, coverage, state and frozen-header artifact instead of accepting well-shaped digests. This rule was strengthened after the V3 Graph registry omitted 1,452 genuine canonical pools carrying 6,148 requested event logs in one completed shard, while one additional canonical-claiming address carrying four swaps failed CREATE2 identity; successful pagination and row decoding had both passed while the provider-defined pool perimeter remained incomplete.

**A fresh-source adjudication must be acquired, not supplied.** The release runner derives its comparison calendar from the complete installed perimeter, fetches that frozen calendar through an executable independent path into an isolated output root, and retains the exact provider query, response or result identity, endpoint, retries, code blobs and selected-field contract. The query fields must cover every load-bearing field consumed downstream, including amounts, turnover, invariant parameters and token weights; its time bounds and pagination key must equal the active consumer contract, and its cited code must be the code that issued that query. A caller-provided ledger, copied legacy bytes, an unrelated valid commit or a well-shaped query manifest cannot clear the gate. Finalization recomputes identities and signed quantities from both retained payloads, requires zero exceptions, and verification reopens the installed raw partitions against the certified logical hashes before any D3 reader can proceed. This gate was added after a green synthetic test minted a zero-exception certificate by copying the legacy ledger into the nominal fresh-source slot while omitting several fields that determine turnover and pool state.

**A state replay starts at the protocol's initialization event, not its first observed trade.** D1 must identify and certify the event or state transition that makes each object usable, list every state-changing event that can follow it, and prove their precedence and uniqueness contracts before D2 replay. Factory creation metadata is not an initial price, first-swap post-state is not pre-swap state, and liquidity changes before the first swap cannot remain invisible. Sparse initialization logs may live in their own immutable generation when adding them to a completed high-volume generation would force an unrelated refetch, but that generation must retain the same frozen-header and exact RPC evidence and enter the canonical state fingerprint. Replay creates state at initialization, applies every later event in exact block-transaction-log order, and records zero initialization, duplicate initialization, pre-initialization mutation and unsupported dynamic or hooked behavior as explicit support outcomes. A first-event audit must then test every protocol family on the full calendar and the registered validation subset; any chosen or candidate route whose pre-transaction state depends on an omitted initialization event reopens D2. This gate was added after concentrated-liquidity replay instantiated pools only at their first Swap, hiding funded pre-swap intervals and making the first swap itself impossible to quote from certified pre-state.

**Independent evidence must be information-efficient and honestly bounded.** Before registering a new evidence population, quantify its expected calls, bytes and wall time and test whether retained exact chain evidence already contains the same transaction, log and signed-payload fields; duplicating those fields through per-transaction receipts adds cost, not independence. If a full census is infeasible, freeze the validation calendar before inspection, reopen every selected unit, report calendar coverage and the exact zero-failure upper error bound, and state the exchangeability and unsampled-day limitations. A sampled validation release may license a separately labelled provider-derived full panel only through that explicit gate; it is never described as a full-history source certificate.

**Provider order is evidence, not an identity convention.** Ethereum receipt `logIndex` is block-global. If two different provider events claim one block-log position, do not widen the causal key with transaction hash or mutate the provider capture. Reconcile the complete affected provider block span against global topic-only Ethereum logs, matching exact transaction, pool, event class and quantities. The immutable provider files remain evidence; one hashed reconciliation generation records order overrides, collapsed provider duplicates, exact payload overrides, ignored zero-state events and exact-chain supplements for omitted state-changing events. A supplement enters canonical state only with canonical pool statics, exact base-unit decoding and independently retained block-timestamp evidence. An unmatched provider event, ambiguous match, missing static, unproved timestamp or unsupported payload difference keeps the partition red. The generation and all exact evidence enter the canonical state fingerprint. This affected-span repair does not substitute for the independently defined full-day completeness certificate, and even a complete provider-day span does not certify cumulative state before that day.

**State admissibility and quote-validation admissibility are separate.** An independently verified event that changes reserves enters causal state even when its net token deltas do not describe an ordinary one-input, one-output trade. A V2 Swap can contain excess input on both sides; both-positive or one-sided net reserve movement is therefore an exact state update but cannot validate a standard constant-product quote or enter a realised execution-cost sample. Quarantining that event from state makes every later quote in the pool wrong. Canonical rows carry `usable` for state reconstruction and `quote_supported` for economic quote use, and no parser may collapse those flags into one screen.

**A runner has one data role.** An ingestion/materialisation runner may read raw provider records and write a versioned canonical partition or analysis-ready panel; it may not report a paper estimate. An estimator may read registered canonical inputs and write results; it may not parse provider records. The findings audit resolves active producers from the specification and model ledgers plus artifact provenance, so adding a claim or model automatically expands the raw-boundary scan. It also verifies every registered claim input exists with current provenance. Both full perimeters are generated independently of observed files: 12,802 directed-route venue-days across eight venues and 11,009 quote-state family-venue-days across six. A missing primary stream therefore creates a failed partition instead of removing its date from the denominator. Each unified route day carries an input-aware marker over its exact launched-venue swap partitions, output identity, exclusions, duplicates and conflicts. A raw repair invalidates that day mechanically. Partial route or state builds never publish or overwrite a cumulative global ledger.

**A construction release must re-derive its semantics.** Provenance, row counts and schema are necessary but do not establish that a large panel means what its columns claim. The release audit independently checks the economic-cell key, formula identities, availability flags, path and source lineage, canonical scientific scope, and quantities that should remain invariant when one input is repeated across alternatives. The route-cost release therefore fails if direct and indirect availability disagree with quoted output, signed cost cannot be reproduced from those outputs, a path lacks an admitted source/pool identity, a direct quote changes only because the candidate intermediary changes, realised support changes across quote size, or any date contains a duplicate economic cell.

**A quote grid selected on realised intermediation is not a market census.** The main route-cost generation prices the 200 most heavily intermediated directed pairs on each day because those are the economically relevant vehicle markets, but that selection can change mechanically with the outcome the paper explains. Its levels and within-cell comparisons are descriptive for that selected support. Time change beyond the daily selected mix receives two predeclared checks: a fixed cohort of the top 200 directed pairs by aggregate intermediary volume over the first 365 released days and a persistence-cohort profile over alternative rank caps and minimum-presence rules. Top 200, the first 365 days and any retained-share rule are named sample constructions whose composition and sensitivity are reported; no round-number cap or minimum pair count is a scientific admissibility threshold by itself. These cohorts describe established or persistently active vehicle markets, not the market as a whole. Candidate, pair, hour, notional and date dependence also make row-i.i.d. t-statistics invalid no matter how many quote cells the panel contains; the construction summary reports support and distributions only, while inference aggregates or clusters at the predeclared economic assignment and calendar levels.

**Dependence follows every repeated economic dimension that can carry a common shock.** A pool-month panel is serially dependent within pool and cross-sectionally dependent within calendar month, so its primary covariance is two-way clustered by pool and month; either one-way covariance is a sensitivity, not the headline. A quote-cell panel repeats endpoint pairs, dates, hours, candidates and notionals, so inference must first aggregate to the estimand's unit or use the predeclared pair and date clustering. A large row count never substitutes for independent assignment units, and every Wald test uses the same admitted covariance as its component coefficients.

**Same-token counterfactuals have one output mark.** Rank realised and counterfactual routes in output-token units, which needs no external price. When gas or economic magnitude requires dollars, convert the difference between their output quantities with one common output-token mark. Never mark the counterfactual output with an external price while retaining a separately reconstructed USD value for the realised output: the mixed basis can reverse the route ordering. Keep reconstructed component USD flow as a validation object, and require the common mark to reconcile to it on every strict dollar-support arm.

**Native granularity is upstream; aggregation is downstream.** When a source carries transaction, block and event identity, the immutable and harmonised layers retain the highest scientifically relevant resolution and any daily, weekly or monthly series is an explicit derived output. For gas, realised transaction cost uses receipt-level gas used and effective gas price joined to the same block's header, base fee, number and hash; an unexecuted alternative combines candidate-specific gas-unit estimates with the focal transaction's exact fee environment. A daily gas series may serve a separately named descriptive or aggregate-control estimand, but it cannot price transaction-level execution or replace causal timing. Apply the same rule to prices, liquidity and protocol state: aggregation is admitted only when the estimand is defined at that level and the information loss is recorded.

**A validation tolerance must sit below the estimand's scale.** A high reproduction share does not validate basis-point effects when the pass band itself is 100 basis points. The transaction-state frontier separately re-quotes the realised first leg, the second leg at its observed input, and their composition; the route is rejected when the maximum absolute error exceeds 1 basis point, with nested 0.1- and 0.01-basis-point samples pre-registered on that same maximum. This prevents two leg errors from offsetting in the final path output. The prior generation's path-only check retained 99.94%, 99.86% and 99.68% at those cutoffs, so the replacement audit must establish the support retained by the stricter leg-level contract before estimation.

**Chosen-pool reproduction does not license a counterfactual pool.** A V2 hour whose end-of-hour reserves can be unwound but cannot be bridged exactly to the previous observed state may attempt same-size reproduction only for its identified realised pool. Passing the leg-level output gate admits the realised route as the baseline; the pool stays outside alternative-route enumeration. A V2 pool enters the public frontier only in hours that pass reserve continuity after all observed swaps, mints and burns are replayed.

**Chosen-state coverage, conditional reproduction and verified coverage are different objects.** Reproducing most available chosen quotes says nothing about routes whose pre-transaction state could not be reconstructed, while quoting nearly every route says nothing about how many quotes pass the leg-level tolerance. Every frontier support ledger therefore reconciles eligible routes to available quotes, mismatches, verified routes and other terminal outcomes. Before any maturation fit, E reports verified coverage, $(\text{available}-\text{mismatched})/\text{eligible}$, in every primary year; its best-worst spread; included-versus-excluded composition; economic-weight coverage; and concentration by venue, family, pair, candidate and regime. The former 80% annual floor and 10-percentage-point spread remain visible dashboard references but no longer block estimation. The result is restricted, reweighted or withheld from promotion only when a calibrated bound or fixed-support comparison shows that coverage selection can materially create the claimed time pattern. Venue-family selection remains required because a pooled pass cannot establish representativeness; rising state availability or validation success can otherwise look like improving routing efficiency.

**External-market support is positive and address-resolved.** A token enters a CEX-reference robustness sample only when a validated source resolves its exact contract address to an observed CEX pair and supplies dated price observations. Ticker equality alone is insufficient, and absence from a selected publication package never means unlisted. The current bounded registry reproduces the 43 exact Uniswap--Binance matches in Lehar and Parlour's published package after applying the authors' reserve/volume screen, downloaded-symbol intersection, densest-pool rule and two ticker-collision exclusions. Its 4,113 rows are a 1-in-10,000 minute audit sample from 2020-05 through 2022-12, so first and last observations define a conservative positive-support window only. It can bound the V2 rent result on observably cross-listed tokens over that interval; it cannot classify the long tail, support a full-sample listing control or turn unsupported dates into zeros.

**Pool capital, local depth, executable band depth and LVR scale are different canonical quantities.** A protocol-family layer materialises each quantity independently when its own contract is ready; it never fabricates a complete row by copying one field into another. `capital_usd_lagged` is deposited pool wealth at the exact prior calendar date, built from token balances or range inventories and valued with a separately validated price source. `local_depth_usd` is invariant-specific marginal curvature at the measured state. `band_depth_usd` is executable inventory inside a stated price band or notional. `lvr_scale_usd` is the contemporaneous invariant-specific wealth scale used by an admitted LVR formula. Full-range constant product creates identities among some of these objects, but those identities do not transfer to concentrated liquidity, StableSwap, weighted pools or hook-based pools. Return and APR estimators fail closed unless their denominator is finite positive lagged capital with non-depth provenance. Dollar LVR, price impact and routing capacity use the venue's declared invariant adapter; the presence of any field called liquidity or TVL licenses none of them. For a released full-range constant-product family, exact closing reserves, exact pool identities, audited decimals and independent address-day prices own scientific capital; provider `reserveUSD` or TVL is an optional overlap diagnostic and never determines row eligibility. Pool rows, candidate allocation, rejection ledger, overlap materiality, provenance sidecars and the complete shard and upstream identities form one immutable generation selected by one marker-last pointer. Every reader resolves that pointer and cannot mix files from different generations. Provider capital may become scientific capital for another family only after row-level reconciliation to separately valued holdings. Reconstruction, validation, exact-calendar lag, provider-overlap materiality and the rejection ledger belong to node D; an estimator may filter the released validation status but may not parse raw provider rows, reprice balances, loosen reconciliation or promote a field locally. Uniswap V3 `tvlUSD` failed that audit and is quarantined. Its event-complete replay is an event-accounted pool inventory, not yet deposited LP capital: historical token balances validate custody, while exact protocol-fee claims must be removed before ownership is attributed to LPs. Direct transfers and rebases appear as custody discrepancies and are never silently assigned to LPs. A validation sample may bound the discrepancy but cannot promote an unsampled panel; promotion requires a row-level ownership-reconciled generation, separate valuation and an exact prior-calendar-day lag. A new protocol therefore reopens D1 until each requested quantity's source, construction, timing, callable materializer and validation sample pass.

**The liquidity contract is exhaustive over venue, pool family, state generation and quantity, and it fails closed at the row.** `ddvc.liquidity` owns the protocol-capability registry, and its venue perimeter must equal the canonical DEX source inventory exactly. Each pool-family entry gives deposited capital, local marginal depth, executable band depth, finite-size quote quality and LVR an independent state generation, exact `module:callable` materializer, validation rule and readiness flag. Every custody-based capital construction must separately establish the contract's token balance, the economic claimant and the pool attribution; custody is not ownership. The freeze gate resolves every ready materializer and rejects a module-name string, missing callable or venue-wide label. Every admitted output row carries its pool/invariant family, quantity kind, state generation, validation generation, state timestamp, failure reason, provenance and exact-lag status when applicable; every estimator declares the quantity it requires and the freeze gate checks that declaration against the row contract. Full-range constant product may use separately validated reconstructed reserve value as capital and its invariant for depth and LVR. Concentrated liquidity requires event-replayed or separately reconciled inventories with protocol-owned claims removed for capital, active virtual reserves for local depth and tick-path quotes for band depth; it cannot enter LVR or return inference until a path-integrated LVR adapter passes. Curve StableSwap, CryptoSwap and NG families do not inherit one another's adapters. Balancer weighted, stable, composable-stable, linear, boosted, Gyro and custom pools must be admitted separately through measured out-of-sample quote reproduction; vault balances determine capital only after internal pool tokens, wrappers and rate providers are resolved. V4 vanilla concentrated pools do not authorize hooked or dynamic-fee pools, and all V4 capital remains unapproved until singleton claims are attributed to pools. Fluid's trade-only source authorizes neither capital nor depth. A return denominator whose source, validation lineage, quantity type, family or exact prior-calendar-day status is not explicitly permitted raises an error even when the column is named TVL.

**Quote quality is not depth.** The ratio of output dollars to input dollars at one notional, $O(q)/q$, is `quote_quality(q)`: it combines price level, fees and average slippage. It cannot be named marginal depth or executable capacity. `local_depth_usd` is a derivative of the invariant at a state; `band_depth_usd` is the maximum input inside a prespecified impact band and direction. Every venue's quote adapter applies the same fee-inclusive own-price-impact support threshold, while protocol reversion caps are recorded as additional constraints. Scaling balances must scale capital and band depth without changing marginal price; changing a V3 range, Curve amplification or Balancer weight at fixed holdings may change depth but cannot mechanically change capital. Provider TVL must reconcile to independently valued holdings on a validation sample or remain quarantined. Calibration trades and validation trades are disjoint.

**LP supply flows are built before they are estimated.** An estimator never parses provider rows, reconstructs prices, or classifies ranges locally. Node D orders canonical swaps and liquidity events exactly, classifies a range against the latest strictly prior swap state with `lower <= tick < upper`, records state age, and rejects events with no causal prior state. A V3 event is valued from its exact token amounts, a canonical address-day candidate price anchor and the exact prior `sqrtPriceX96`, with token decimals resolved by address; the nonexistent provider `amountUSD` field and symbol fallbacks are forbidden. Event value is allocated once across candidate sides, so a two-candidate pool never contributes its full value twice. When capital is unavailable, the released objects are dollar gross/net supply flows, within-day candidate shares and net-flow pressure only; their status explicitly says no capital-stock denominator, and they cannot be called flow rates, reallocation rates or returns. A normalized flow may be released later only against exact prior-calendar-day deposited capital over the same protocol perimeter, including pools with zero events. Daily end-state ticks, row shifts, cross-protocol denominators and event-level denominator repetition are prohibited. Mint and burn flows may be called liquidity supply flows or range placement. They may be called repositioning only after a validated controller identity links a burn to a subsequent mint within a stated time window; pool-level mint/burn totals do not establish that construct. The materializer writes accepted events, candidate allocations, candidate-days and a rejection ledger; the freeze gate checks valuation identity, event-value conservation, family/generation identity, causal time and the declared denominator status before any 1-, 7-, 30- or 120-day response is run.

**Construction mode cannot leak inference.** A runner that retains both panel construction and analysis for compatibility must expose `--panel-only` and return immediately after the provenance-stamped panel is installed. D3 invokes only that mode. It does not calculate HAC inference, print claim statistics, or write finding exhibits. E and F may invoke the analysis half only after the specification lock is current.

**Sync and executor handoff.** `origin/main` is the durable handoff boundary across providers and machines. Commit and push every completed, independently reviewable node and every other safe milestone promptly; during continuous work, twelve hours is the absolute maximum between remote checkpoints. Before an anticipated executor switch, push the latest validated checkpoint to `main`; if a coherent change is still under review, push it to one clearly named branch with its current gate result and next action, never onto `main` merely to preserve it. Long builds do not defer safe code-and-documentation checkpoints: exclude partial caches and stale generated manifests, label the commit as non-release when applicable, and keep the active process resumable. After each `main` push, every active clean execution checkout fetches and fast-forwards before taking new work; a dirty historical checkout is preserved as evidence and cannot be treated as synchronized merely because it fetched. Gitignored data move separately through their signed generation manifests and enter another host only after exact content and provenance checks pass. An unpushed completed node counts as unfinished.

**Distributed execution preserves one generation.** A second machine is a bounded worker, not another source of truth. Before it starts, fetch the same committed code, resolve the same scientific scope, record the input and engine fingerprints, and split only independent work whose output ownership is explicit. Every cache count, missing-work estimate and ETA is measured on the designated execution host after that identity check; absence on the controller says nothing about worker coverage. Do not migrate an advanced stateful run merely because another host is faster; let it finish while the second host takes a different ready queue. Raw or generated data crosses hosts through a staging directory, and nothing enters the live tree until the expected file perimeter and a deterministic content manifest pass. The manifest is format-aware: gzip identity is the ordered decompressed payload, since container bytes can vary across compression builds; ordinary byte-stable files use exact bytes; a binary analytical format needs an explicit schema-and-row canonicalizer before cross-environment equality may be claimed. `scripts/audit_portable_content_manifest.py` owns this check for the currently admitted gzip and byte-stable formats. Sharded raw evidence additionally requires one canonical aligned partition, per-shard semantic reopening, collision-free marker-last copying, rejection of gaps, overlaps, alternate ranges and interrupted files, and an ordered root manifest published atomically only after every destination triplet reopens against the same frozen source identity. When the cross-host link is slower than the provider route, the worker may fetch missing raw partitions directly, but it must then pass the same completeness, identity and chain-evidence gates before materialisation. A remote output is not complete until it is installed under the canonical generation, its provenance is current, and the source host's temporary copy is either retained as the named recovery checkpoint or removed after verification. On one filesystem, an immutable marker-complete shard checkpoint may use verified hard links to avoid duplicating large raw bytes; file counts, an exact dry-run perimeter comparison, and inode identity must pass before the copied checkpoint is removed, and the watcher must preserve marker-last semantics. This is durable against deleting either directory entry, but it is not an independent-disk backup and must never be described as one.

**Distributed scheduling follows the dependency graph, not launcher order.** Before launch and after every worker or stage transition, enumerate the ready nodes whose declared predecessors are complete, assign every non-conflicting long-running node to the fastest compatible free host, and record why any ready node remains idle. A watcher may wait only for a real data dependency; it may never serialize disjoint block ranges, calendar partitions, paper-grained source audits or other independently owned shards merely because they share a later assembly step. The assembly or release node waits for all shard certificates and remains the sole publisher. End-to-end ETA is the longest remaining dependency path under measured joint throughput, validation and assembly time, not a machine-speed multiplier or the sum of all work. When concurrent jobs share an RPC endpoint, disk or memory bus, remeasure their joint rate after startup before updating the ETA. Every status report names the current graph node, ready, running and waiting sets, completed and remaining units, observed joint rate, downstream serial allowance and the next release gate. A ready independent shard left waiting on an unrelated dependency is a scheduling defect that reopens orchestration before scientific work continues.

**Long jobs survive the transport session and fail at the first broken stage.** Any node expected to outlive an interactive check runs under a detached session manager or a supervised service on its execution host. Before launch, the wrapper resolves the execution host, checkout, interpreter and every stage executable, then records the committed code generation and ordered stage plan. The preflight must execute through `./scripts/run` and print the loaded project package's `__file__`; the resolved module must sit inside the selected checkout, because an engine identifier alone cannot detect an editable environment silently importing the primary checkout. The child process redirects stdout and stderr to a persistent node-specific log, captures each stage's return code explicitly and writes one atomic completion or failure marker; a failed stage prevents every downstream stage. Within one stage, an expected per-unit upstream failure is captured as a bounded unit failure while independent queued units continue, and the stage fails atomically after the queue drains; one bad request must not abandon hours of reachable work. Do not rely on shell `errexit` inside a command group used as a conditional operand, because that context can suppress exit-on-error. SSH is used only to launch, inspect or resume that host-owned session; a live SSH socket, terminal tab or executor process is never the job owner. A vanished session with no marker is a failure requiring process and artifact verification, not evidence that work continues. Stopping or losing the detached session is likewise not proof that its child exited: resolve and inspect the actual process group, log activity and terminal marker, send `TERM` and then `KILL` only if needed, and verify that no matching child survives before deleting data or restarting the stage. A supervisor monitors both child liveness and terminal-marker freshness and changes the reported ETA immediately when either contradicts the plan; planned throughput is never reported as active throughput. An intentional stop writes a distinct atomic checkpoint marker naming the reason, code generation, completed-unit count and next stage; without it, an external audit must classify the silent runtime as orphaned even when its completed shards remain valid. Resumption begins at the first unfinished stage after every prior artifact passes its own certificate. Completion requires the marker, expected output perimeter and content/provenance validation.

**Live status is part of execution.** Every long node exposes its current graph node and return edge, resolved scope, completed and expected units, active worker and memory bounds, latest gate result, and any intermediate statistic that changes the scientific diagnosis. **The rhetoric lane is enumerated, not closed by example.** The raw-passage ledger lists every current section and subsection opening in source order, the object inherited from the preceding argument, what the opening does, its classification as a substantive bridge, direct opening, or justified roadmap, the raw JFE analogue, and an editorial judgment. **A locked empirical execution spells out every scientific scope argument.** Script defaults are conveniences, not an estimand. **A daily chain-state cut comes from the chain clock, not a provider's last event.** Event-stream metadata such as `max_block` records the latest row observed in whichever stream produced the metadata; it is not necessarily the final block before UTC midnight, and a later mint, collection or donation may exist after it. **Raw mutation and canonical materialisation are one exclusion domain.** Fetch, sparse repair, static enrichment and market-state materialisation acquire the same cross-process raw-data lock. Disjoint-source parallelism is allowed only after the lock is partitioned mechanically by exact source; manual claims that two jobs touch different venues do not weaken the shared lock.

**One transient shard failure does not terminate a long independent queue.** A throttled or gateway-failed raw chunk is requeued at the tail while other independent chunks continue, with bounded per-chunk attempts and an explicit terminal-failure ledger. Two classes of node, and the graph must not mix them up.

*Idempotent gates* cost nothing to re-run and carry no state: measurement, linting, conformance. They run continuously, after every change, and re-running them on unchanged input is free.

*Non-idempotent transforms* consume an input and produce an artefact that has to be regenerated when that input moves: numerical prose, deck authoring (H), figure polish. The working paper and deck remain complete enough to read or present throughout the project. Reproducible provisional results appear at their current scope and refresh in place; only retired, contradicted, or presently irreproducible sentences are withheld. **Freeze irreversible transforms, not learning.** A data or release defect blocks only results whose estimand depends on that defect. A provisional result can enter the working paper or deck at its present evidentiary strength but cannot enter the submission freeze. Calendar-day membership is not enough, and block membership is not enough either. Replay all state-changing events by block and log index, use a strict-before lookup, and include a regression test with a state change between two observations. Both concentrated-liquidity validators once paired the preceding swap's price with the validation day's final liquidity map; this leaked later liquidity into earlier quotes. One shared event-order owner now interleaves V3 mints, V3 burns, V4 signed liquidity changes and swaps. Strict replay covers 1,206 V3 swaps and 4,218 V4 swaps, all inside 1%; V4's p99 absolute error is 0.00000039% and its maximum is 0.000998%. The first “own-block” triangle instrument then repeated the same class of error at a finer level: ordering only by block and using `bisect_right` included the target swap's own post-state and could include later logs from the same block. Strict block-log ordering raised the under-one-minute verdict-flip rate from 15.56% to 22.49%. Reverse state reconstruction has an additional contract: a timeline of per-event pre-states must return the first event at or after the target's pre-state, or the preceding event's post-state. Returning the last pre-state at or before the target omits the preceding swap's effect, while timestamp-only ordering also confounds events in the same second. A coherent unwind is not proof that all reserve changes are observed: replay swaps, mints and burns together, then require continuity against the nearest prior observed reserve advanced through every intervening raw event. An absent immediately preceding clock-hour observation is not itself a failure when the gap contains no unexplained state change; an absent prior state or a residual mismatch is unverifiable support and must be excluded. A validator also has to sample the estimand's population: direct-pool swap times are opportunity snapshots, not realised multi-leg routes, and whole transactions are not reconstructed route components, however precisely their state is ordered.

**Validation failures retain identities, not only counts.** Any validation rule that excludes an observation writes a rejection ledger with the same causal key as the admitted panel, the realised and reconstructed values, the signed error, the failure reason, and the strata needed to localise it by date, venue, pool, and asset. Aggregate failure rates supplement that ledger and never replace it. A pooled threshold cannot pass while the rejected observations are available only as a count, because a venue-era collapse, token migration, or unsupported transfer mechanic can then be hidden inside an acceptable average and cannot be bounded in the estimand.

**Canonical identifiers own aggregation; display labels never do.** Canonicalise machine keys before selecting endpoints, ranking pairs or grouping observations, enforce the expected key uniqueness on every generated shard and final panel, and attach human-readable labels only after aggregation. A display field is metadata and cannot be allowed to split an economic cell. This became an executable rule after native ETH and WETH were correctly unified at the address layer but the route-cost pair selector continued grouping on `ETH` and `WETH`. The result was 1,372,248 duplicated quote cells in the assembled panel, all with multiplicity two. The corrected selector aggregates only on canonical endpoint addresses, rejects components with non-unique canonical endpoints and chooses one deterministic label after the economic cell is fixed. The rebuilt panel contains 123,384,168 unique cells from all 2,277 day shards; deliberately assembling the superseded cache still triggers the duplicate-key refusal and atomically preserves the corrected output.

**Market maturation is a decomposition, not one trend.** A rise in cross-venue paths measures opportunity-set integration. A decline in realised-to-best cost gaps within a fixed reachable set measures search and pool selection. A decline relative to the best direct or alternative-vehicle path measures path and intermediary selection. A change in which currency intermediates routes measures vehicle-currency rotation. None stands in for another, and “the market became more efficient” is admissible only after the relevant margin is named. A routing technology can also move the extensive and composition margins in opposite directions: it may reduce indirect routing by finding direct liquidity while strengthening one intermediary among the routes that remain, or expand indirect routing by activating fragmented spokes. Pre-specify both margins instead of letting one technology story rationalise either sign after the fact. The routing-efficiency branch therefore reports integration, indirect-route incidence, within-vehicle search, path selection and vehicle choice as separate estimands before it asks whether they move together. Quote-size interpolation also has an identity contract: the winning intermediary, venue sequence and exact pool sequence must be unchanged at the bracketing sizes. If any of them switches, interpolating the two winners constructs a path that was never quoted and the cell is quarantined. Even a stable-path interpolation remains provisional until exact-size transaction-state re-quoting validates its error distribution. The benchmark decomposition is a validation and conditioning device, not a novelty claim: `docs/router-identification-feasibility.md` owns the prior-art boundary and records the binding Xi and Moallemi overlap.

**Topology, valuation and support are separate contracts.** Directed token flow determines whether a component is economic, which tokens are endpoints, whether it contains an intermediary, and whether multiple legs are a direct pool split or a sequential path. A leg-level dollar estimate may audit and weight that object, but it never defines the object. Count results use the topology-valid clean-leg perimeter; value results report raw weights plus nested source-to-intermediary-to-sink coherence bands. Every support label names its axis in the output schema. In particular, route-flow coherence and quote-grid notional proximity are two dimensions even when both happen to use 2x and 20% bands; a paper-facing restriction must state whether it applies to one or their intersection. This rule was made executable after multi-leg routes were found to include direct pool splits and a quote-size screen was described as valuation coherence.

**A fixed-cost calibration carries its own support hierarchy.** Route gas is measured from receipts on exact one-component transactions, first matched by year, leg count, venue sequence and intermediary. Missing exact cells fall back through named levels, and every applied estimate records the level, contributing cells and transactions. Broader levels aggregate prespecified cell medians instead of raw selected receipts, so a vehicle with more sampled transactions cannot acquire extra weight accidentally. The main estimate uses the matched median and reports an interquartile sensitivity; it does not call marginal quartiles a confidence interval. Total receipt gas includes router approvals, transfers and bookkeeping beyond AMM execution, which is part of the trader's realised cost but prevents interpreting the level as a pure per-hop technology parameter.

Until then, develop the prose input in `docs/paper-spine.md`. The discovery register is correct there because a record is judged on whether it is complete and traceable and never on whether it reads like the venue. Do not create a parallel style memo.

**The transform must be a FUNCTION of its input, never an edit to it.** Node P writes `paper/` from `docs/paper-spine.md` and leaves the spine untouched. That is what makes it re-runnable: when a finding changes, the affected section is regenerated rather than patched, and patching is the mode that was measured not to converge. Rewriting the spine in place as publication prose would destroy the input and make the second run impossible.

**A gate that cannot pass yet must REPORT and not FAIL.** While `paper/` does not exist, the shape gate measures the memo and reports the distance the rewrite has to travel, which is useful. Wiring that distance into a red build would leave conformance permanently red, and a permanently red gate trains everyone to ignore it, which is how a real failure gets missed later.

**Conventions come from the corpus in BOTH directions, and one direction alone does not converge.**

*Subtractive half, already in place.* When a stylistic tell is suspected, it is added as a PROBE to `scripts/measure_prose_conventions.py`, and `scripts/find_prose_outliers.py` discovers candidate tells nobody named first. Both report the draft's rate per thousand words beside the published corpus. Declared probes can enforce a known house-style decision; the unsupervised list is advisory because an unusual rate can reflect the paper's subject, a genuine rhetorical habit, or a false sense classification. Its role is to direct contextual reading, not to trigger automatic synonym replacement.

*Rhythm diagnostic, added 2026-08-06 because the subtractive half was measured to be insufficient.* `scripts/measure_venue_shape.py` reports sentence length and its long tail, commas, subordinate clauses, paragraph-length dispersion, heading grammar, heading structure, and the share of sentences that open on information the previous sentence already carried. These measurements diagnose suspicious regularity after a passage is written; they never supply a template for writing it.

**Logical cohesion is reviewed at the level of the proposition, not the connective.** Each sentence must define an economic object, supply evidence about it, draw an inference licensed by the preceding evidence, or move to a named new question. A definite article or pronoun resolves to an immediately available referent; “therefore,” “because,” “so,” and similar links state a conclusion or mechanism supplied by the neighbouring sentences; a contrast names an economically relevant alternative; and a list appears only when the argument later uses its members. When one of these relations fails, rewrite the paragraph from its economic proposition instead of replacing the offending word. The raw JFE passages used for the section review supply positive examples of how claims are introduced, qualified, connected to design, and handed to evidence. This is an editorial reading rule, not a sentence template, paragraph-length target, or permission to imitate surface syntax.

The grounding is a measured failure. Forty-two clean deletions of a banned construction moved the discovered-tell count by a third and moved both gates by nothing, because deleting a tell never installs a convention. Three findings from that round:

- **The draft was lexically saturated.** Nearly every candidate replacement was already at or past its own corpus ceiling (`bound` -18 occurrences of headroom, `threshold` -19, `quote` -35, `reading` -28). A document with no vocabulary headroom has a sentence-architecture problem, and word substitution has nowhere to move.
- **Shape survives synonym substitution.** Rewriting "and not at economics" as "and never at economics" changed the word and kept the banned correction-by-negation shape exactly.
- **Over-correction is invisible to the subtractive gates.** A first pass on section 3 cut the median sentence from 26 words to 14 and the venue's long tail to zero. Every subtractive gate approved. Only the positive bands caught it.

*The two checks have different consequences.* The subtractive house-style rules bind final prose delivery because they encode Java's voice and known machine-writing tells. The venue-shape measurements are advisory smoke alarms: a systematic departure triggers contextual reading, but it never fails a section and never licenses editing toward a number. Neither device outranks scientific substance.

*A target computed from a varying corpus is not a target.* `measure_venue_shape.py` treats an exemplar that fails to extract as FATAL. The first version swallowed timeouts, so bands were silently computed from twelve papers instead of fourteen and moved between runs on identical inputs, and a section measured against one run was judged against a different ruler on the next.

It remains true that the corpus uses em dashes, "rather than" and three-item lists freely, so those are venue conventions and any ban on them is an author preference that must be labelled as one and not confused with venue conformance.

**An inferential or conditional comparison is not a result until its conditioning set is explicit.** Raw rates, shares and differences can be important descriptive facts, but they do not become conditional or causal findings merely through prominence. Every inferential headline comparison states its estimand, fixed effects or conditioning set, controls where economically required and dependence-robust inference. A descriptive headline is labelled descriptive, gives its population and denominator, and does not borrow regression language. The failure this prevents: a turnover hazard ratio of 1.17 was reported from unconditional pair-day rates before any absorption was applied.

**Controls diagnose a coefficient; they do not manufacture its preferred sign.** Every control ladder starts from exact common support and adds predetermined market state before any contemporaneous mechanism. Each rung reports the uncontrolled estimate on that rung's retained sample alongside the controlled estimate, so a coefficient change caused by observation loss cannot be mistaken for omitted-variable correction. Gas conditions, lagged volatility, lagged stress or depeg state, endpoint demand, fee architecture and predetermined opportunity-set measures are admissible baseline controls when their timing matches the estimand. Contemporaneous liquidity, capital, route availability, candidate count, pool choice and realised reach may be consequences or mediators of vehicle status; they enter separately labelled mechanism or mediation specifications unless the design establishes that they are predetermined. A sign change across venue, era, stress or opportunity-set strata is tested as heterogeneity with explicit interactions and joint contrasts, not hidden by searching for a control set that stabilises one pooled coefficient. Every coefficient family therefore distinguishes support change, conditional-association change and mechanism attenuation before any economic interpretation.

**Independent review.** Reviews that matter use a clean-room specialist selected from a different executor family through the portable role interface (`glotl review <role> <artifact>`), with the authoring executor and private discussion withheld. Grounding: a nine-judge same-family panel was measured to carry the independent information of about two votes, because shared training produces shared blind spots and a judge inflates its score when it shares the mistake being judged. Same-family redundancy buys confidence without accuracy. The workflow contract names the review role and independence condition, never a provider, model or host-specific command flag.

**No internal process in any deliverable.** No slide or paragraph reconciles the work against its own earlier plans, renumbers propositions, references pipeline phases, or opens with limitations. Reporting a null is mandatory and belongs in results, stated as a finding. Performed uncertainty at the reader is a different thing and has no place there.

**State the supported result affirmatively; consolidate identification boundaries.** The empirical ledger records whether an estimate is descriptive, quasi-experimental or causal, but the paper does not append an unproved opposite to each supported sentence. Say that two variables are associated, or that one change is larger in a named regime, and reserve non-identification, alternative explanations and caveats for the design paragraph or a consolidated discussion where they materially govern interpretation. Full-text inspection of the 14 JFE exemplars supports this placement: ten never use “causal” at all; explicit noncausal caveats in the descriptive papers appear at the design boundary or in discussion/conclusion, while papers with natural experiments or instruments make affirmative causal claims. This rule never licenses causal verbs for a descriptive design.

## 1. What the venue appears to require (node A output, literature audit reopened)

The existing profile reports results from a fourteen-paper JFE venue corpus, and the current paper spine reports a nine-paper architecture subset. The underlying PDFs and aggregate measurements survive, but “full detail in the agent output” does not. Treat every count below as provisional until its denominator resolves to completed full-text cards in `docs/literature-audit.md`; the audit must cover both scientific content and venue craft paper by paper.

**Architecture rules supported by the corpus:**
- No standalone literature-review section (14/14). The review sits inside the introduction, each strand closing with a differentiation sentence.
- No H1/H2 hypothesis list (0/14) and no testable-predictions exhibit (0/14).
- If there are numbered results, use Propositions, not Theorems (1/7 uses Theorem), follow each with prose intuition (7/7), and put proofs in an appendix (7/7 have none in the body).
- State one central mechanism at rising levels of formality in the abstract, introduction and results.
- Name and dispatch load-bearing objections in the body; an appendix does not discharge them.
- Translate magnitudes into economic units in prose.

**Measured architecture references and anomaly alerts, not scientific gates:**
- Introduction 5.5–8 manuscript pages, 12–18% of the document, narrating the argument in prose before notation and previewing every finding.
- Six top-level sections, ±2, ending with the Conclusion. The count is a design target, not a reason to reject a stronger architecture.
- Abstract around 100 words (median 101, 11/14 within 96–106), opening with what the paper does and avoiding gap-framing. Coefficients, t-statistics, sample periods and sizes appeared in none of the 14; 10/14 contain no numbers, but absence is a soft convention rather than a ban.
- Roughly 8 tables and 7 figures for an empirical paper. The exhibit hierarchy and the work each exhibit performs matter more than matching the counts.

**Idiosyncratic, so choose deliberately and do not assume:**
- **Having a model at all: 8/14 yes, 6/14 no.** A prior claim in version 1 of this workflow that JFE requires model-first structure was wrong on both halves and is retracted here.
- **Model before empirics, among papers with both: 1 of 3.** Huang, Ranaldo, Schrimpf and Somogyi state theirs is "a static partial equilibrium model that rationalises the two main empirical findings from the previous section." Facts first, model as rationalisation, is at least as safe.
- **Causal identification of any kind: 3 of 9 empirical papers.** 6 of 9 make no causal claim, two saying so in the text. Only 2/14 use a natural experiment as the identification spine. What substitutes, in every one of the six: **a data moat plus an obsessive validation apparatus.** Graham et al. spend the whole second half of the paper defending the data source.
- Length 20–45 typeset pages, median 23; roughly 45–60 manuscript pages. This is an optics target and anomaly alert, not a scientific veto.

**The strategic reading.** The distribution is bimodal: 5 pure theory, 6 pure empirics with no formal theory, only 3 doing both. Attempting both is the minority strategy. **This paper takes the pure-empirics lane**, because a model added to reach for respectability would be the third-least-common configuration in the sample. Caveat recorded from the independent review: counting structural features across 14 papers describes what published papers look like and does not establish what caused acceptance, so this is a presentation-architecture decision and carries no claim about acceptance odds. A model is added later only if a specific empirical coefficient or threshold cannot be explained without one.

**Craft pattern to adopt deliberately: the named rival mechanism run as a horse race.** This is what no-model empirical JFE papers use in place of formal hypotheses. Bolton and Kacperczyk italicise three competing hypotheses in the introduction, use them as running labels structuring the results, and reject one of their own.

**Passage-grounded rhetorical grammar; the published text, not the cards, governs imitation.** The cards locate arguments and record architecture, but they are not sentence-level style evidence. Before rewriting a section, read the named raw passages below and compare the proposed section with the closest economic analogue. The recurring moves are evidence from several accepted papers, not a universal template or permission to copy a paper's verbal quirks.

- **Introductions admit distinct argument forms.** Li, Ye, and Zheng move from a market-design surprise to two economic questions, then separate gross price, net price, execution probability, and clientele mechanisms (`literature/text/2023-LiYeZheng2023Refusing-refusing-the-best-price.txt`, lines 36–230). Bolton and Kacperczyk turn disagreement about carbon pricing into three named rival hypotheses before presenting the estimates that discriminate among them (lines 112–195 and 234–381 of their raw text). Chang et al. lead with the network-propagation question, establish identification with two local shocks, and only then generalise to return predictability and real outcomes (lines 63–271). Graham et al. instead organise an observational survey around three question blocks and announce the selection, response-validity, and omitted-variable limits with the validation design (lines 83–108 and 258–388). Huang et al. use a model-led mechanism-and-implication sequence. The common discipline is not a stock opening: define the economic object, explain what remains unresolved, show why the design can distinguish relevant explanations, report the main magnitudes, state only the interpretation earned by that design, and then locate the contribution.
- **Anecdotes, analogies, and transaction cases have jobs, not quotas.** Mayer opens with Theranos, extracts the hidden-failure financing conflict, and moves directly into the model (`literature/text/2022-Mayer2022FinancingBreakthroughs-financing-breakthroughs-under-failure-risk.txt`, lines 62–80). Bolton and Kacperczyk use named institutional voices and Exxon's borrowed "beauty competition" phrase to establish a live disagreement before stating the pricing test (lines 87–120). Graham et al. use executives' "walk the talk" description only long enough to separate values from norms and operationalize both (lines 109–138). Carletti et al. use the named Italian tax reform, dates, quantities, and contract differences to motivate variation, then hand the narrative to the empirical design and first stage (lines 120–199). Lehar and Parlour decode one named blockchain transaction and its logs before returning to their population reconstruction (`literature/text/2024-LeharParlour2024Uniswap-decentralized-exchange-the-uniswap-automated-market-maker.txt`, lines 2320–2338). The ledger in `docs/reviews/paper-rhetoric.json` records the rhetorical job, evidence handoff, and fresh line-range fingerprint of each precedent and each current draft use. The checker invalidates that judgment when a reviewed passage changes. It never requires an anecdote, sets a length, or turns these distinct passages into a prose mold.
- **Results paragraphs follow the scientific dependency, not a fixed sentence stencil.** In fact-first passages, an inherited result creates the next economic question; the paper defines the comparison, points to the exhibit, reports magnitude and inference, interprets that comparison, and exposes what remains to be tested. See Makarov and Schoar's move from low high-frequency correlation to cross-exchange dispersion and then within- versus across-region integration (lines 860–1135), and Chang et al.'s move from event transmission to slower general information diffusion (lines 797–829). In prediction-first passages, the mechanisms generate an ordered set of tests and the results are reported in the same order: Li, Ye, and Zheng state the cross-sectional, time-series, and difference-in-differences predictions at lines 981–1010 and return to them one by one at lines 1057–1130. Bolton and Kacperczyk open a subsection with the exact remaining alternative, specify the coefficient that answers it, give economic as well as statistical magnitude, and carry the survivor to the next rival test (lines 1221–1260 and 1635–1702). Use whichever form matches this paper's scientific object; do not force every paragraph through all moves.
- **Transitions arise from unresolved economics.** “In the previous section” is useful only when the prior finding logically supplies the premise for the next test, as in Li, Ye, and Zheng at lines 981–1010. A “natural follow-up question” earns its place when a result opens a genuinely new market or mechanism margin, as in Chang et al. at lines 1446–1478. Robustness and mechanism sections begin by naming the live alternative or vulnerability, not by announcing that another workflow task will run: compare Chang et al. at lines 1321–1347 and 1369–1380, and Graham et al. at lines 2577–2624.
- **Interpretation strength follows design strength.** Chang et al. reserve causal language for their natural experiments (lines 99–152) and use “consistent with” or “supports” for timing and mechanism patterns (lines 1404–1445). Graham et al. call their study observational, report associations, state that causal claims are unavailable, and then explain exactly what their external validation, controls, and placebos can mitigate (lines 95–108, 220–236, 258–388, and 2404–2429). Bolton and Kacperczyk use a horse race to reject divestment as a sufficient explanation while retaining pricing language commensurate with their return design (lines 342–381 and 1886–1898). A descriptive result here is therefore written affirmatively as a descriptive result; “consistent with” narrows an interpretation only after a named rival, timing pattern, placebo, or heterogeneity test has done work.
- **Claim calibration uses the published papers as positive controls, not an imagined maximally cautious referee.** No language reviewer is “unbiased” merely because authorship and project history are hidden: its training may already contain the published articles. Clean-room review therefore reduces project anchoring but never establishes independence from the literature. For each proposed headline, read the closest raw published passages and record the paper's literal design object, strongest headline, adjacent qualification, auxiliary mechanism evidence, and remaining stretch. A reviewer may hard-block a contradiction between the claim and the measured object, identifying variation, timing, support, or inference. It may not veto forceful framing merely because a methods-only paraphrase would be narrower when comparable published JFE language survives through a nearby caveat or an explicit discussion of alternatives. Published overreach remains overreach, but its frequency calibrates false positives: it is a warning and rewrite target, not automatic evidence rejection. The deliverable should sell the largest economic interpretation that the evidence ladder and adjacent qualifications can carry.
- **Section endings close an evidence chain.** Li, Ye, and Zheng's conclusion returns from the 62% pricing fact to the fee mechanism, clientele segmentation, and policy implication (lines 1848–1901). Chang et al. close by restating what the natural experiments identify separately from the broader predictive evidence (lines 1883–1932). Graham et al. close an observational paper with measured facts and the ingredients a future theory would need, rather than upgrading correlations to causation (lines 2652–2714). A section in this paper should likewise say what the evidence establishes, what explanation remains viable, and why the next section is needed. It never closes with a pipeline state, certificate, or self-assessment.

These rules govern both tiered manuscript work and the later full P rewrite at the level of economic argument, paragraph sequence, and sentence function. `docs/paper-spine.md` remains the source for unresolved alternatives and data-dependent claims that have not reached their evidence tier. Venue-shape metrics and vocabulary lint diagnose the resulting prose only after the semantic rewrite; they cannot generate it.

## 3. Definitions to settle first (node C, blocking)

**Vehicle status and dominance are separate axes.** Vehicle status is a role that is binary and trivially satisfied: one bridging swap qualifies. What matters and what we measure is the *extent* to which one asset captures that role. The literature uses "vehicle currency" as a categorical label for what is really a continuous share, and making that precise is part of the contribution. Working title, a one-word insertion into the original public title so the public record stays continuous: **"The Making of Dominant Vehicle Currencies: Evidence from DeFi"** (decided by Java, 2026-08-06).

**Asset types before tickers.** DeFi is the laboratory and the claim is about currency types, so tickers appear only as proxies:
- *Native platform asset*: the platform's own settlement asset, classified independently of its pairing degree, volume, depth, route cost or volatility. Proxy: WETH. TradFi analogue: the incumbent international currency whose role may rest on thick-market externalities.
- *Stable numéraire*: low volatility, unit of account. Proxies: USDC, USDT, DAI. TradFi analogue: the managed or pegged stable unit.
- *Imported store of value*: non-native, wrapped. Proxy: WBTC. TradFi analogue: gold or a foreign reserve asset.

The general question is then venue- and coin-independent: does the vehicle role stay with the platform-native incumbent or migrate to the low-volatility numéraire, and what triggers migration? Pairing degree, volume, depth and cost are candidate explanations, never definitional inputs. That is the FX dominance-transition question, and we can observe the road not taken where FX cannot.

**Definitions belong on a slide and in a numbered subsection**, stated explicitly.

**What the route-cost experiment measures, stated once so it stops drifting.** For one trade, meaning a specific token pair at a specific hour at a specific size, the panel computes the best ONE-HOP route, which is the direct pool joining the endpoints priced at its cheapest venue, and the best TWO-HOP route through each candidate vehicle, where each leg independently picks its own cheapest pool across every available venue. It then asks whether routing through the native asset costs less than routing through the stable numéraire or the imported asset. Legs genuinely do cross venues: 32.3% of two-hop routes in the current panel have their two legs on different DEXes.

**Why this object and not realised swaps.** Vehicle-currency theory says the incumbent retains the role because routing through it is cheaper, which is the thick-market externality. The test is therefore the cost of the road not taken. FX data cannot run it, because the quote for the route nobody took is never observed; on-chain the state can be reconstructed and the counterfactual priced exactly, which is this paper's actual edge over the FX literature. What the panel does NOT measure is router behaviour or revealed preference. It is the cost surface a router faced, not the choices it made, and those are different papers.

**Consequence for venue coverage, which follows from the definition rather than from tidiness.** "Best available route" is defined over all venues, so truncating the venue set understates the best route on every leg and the bias direction depends on which routes lose most. Curve carries roughly 85% of Uniswap v2's volume on sampled 2024 days and sits where stable-to-stable legs happen, so omitting it plausibly penalises stable-vehicle routes hardest and flatters the native asset in exactly the comparison the headline rests on. Venue completeness is therefore part of identification here, not a robustness appendix.

**Balancer's coverage bound, signed (2026-08-06).** Balancer is the sixth venue and its weighted pools now price exactly: `ddvc.pricing.weighted` reproduces realised swaps at 0.0000% median absolute error with 100% of quotes inside 1%, scored on trades no fit ever saw, across twelve days spanning 2021-04 to 2026-02. Two things had to be identified from data before that held. The daily `poolSnapshots.amounts` record is the balance after the day's LAST event, so netting the day's flow off it and replaying forward gives per-swap balances; the two rival readings of that field score 1.7% and 2.8% on the same trades. And the flow has to include joins and exits, because a swap-only walk charges every liquidity event to the invariant and drops coverage from 87 of 105 testable pool-days to 177 of 367. The bound that remains is real and it is large: 256 of 473 testable pool-days price, and the excluded pools carry a median 91.8% of tested swap volume. The exclusions are decided by achieved fit error and not by pool type, and reading the types afterwards says what they are, namely the boosted and linear families and composable-stable pools.

That is wrong for the two largest of them and understates the work for the rest. AaveLinear and ERC4626Linear, which carry a median 58.8% and 63.7% of a day's swap volume in the exclusion ranking, are not StableSwap at all: they hold `lowerTarget`, `upperTarget`, `mainIndex` and `wrappedIndex` and price a wrapped position piecewise with different fee treatment inside and outside the target band, so they need their own module. ## 4. Candidate results, screened for non-mechanicalness (node E)

### 4.0 What is taken, what is open, and where incumbency can legitimately live

Two independent cross-family reviews plus a four-lane prior-art sweep settled this section. Revised 2026-08-05. The earlier version was wrong in three ways, retracted here explicitly.

**A realised route does not reveal trader habit.** Conditional on a router's information, objective and integrated opportunity set, its optimisation can mechanically select the currently cheapest route, so an incumbent intermediary appearing when a reconstructed direct route is cheaper does not by itself identify trader inertia. The apparent mistake may instead reflect stale state, gas, private liquidity, MEV protection, a restricted venue set or a software default. Version 1's plan to read a wrong-signed cost coefficient directly as Krugman/Eichengreen inertia is retracted. Persistence can still reside in the routing system's slowly updated opportunity set or objective, which must be measured as institutional state instead of assigned to traders.

**Adjacent work exists and must be cited.** Xi and Moallemi (2026) audit 2.98 million WETH-USDC swaps, comparing realised routes with support-constrained, full-venue and gas-aware full-venue optima; their paper is forthcoming in the Financial Cryptography 2026 workshop proceedings. It reports a 2.02-basis-point mean shortfall and $24 million aggregate, identifies failure to activate additional pools as the dominant loss margin even after gas, and shows that state staleness materially enlarges measured shortfall. Their scope is parallel allocation across pools for one endpoint pair on Ethereum L1 and explicitly excludes intermediate tokens and multi-hop routing. That boundary preserves this project's vehicle-currency question, but it does not erase the methodological overlap. Citation duty follows intellectual proximity, not venue rank or the citation frequency of a JFE exemplar set. The paper must cite Xi and Moallemi, concede that realised-versus-optimal routing audits and the support-versus-public-opportunity decomposition are prior art, and establish every empirical object it uses from its own data. Our contribution begins at sequential intermediary choice, vehicle-linked liquidity and long-run vehicle formation, rotation, or persistent replacement after routing maturation is held fixed.

**The entry contract does not identify the aggregator.** The earlier text asserted it did, which contradicted `docs/router-identification-feasibility.md` in this same repo. Corrected: `sender` identifies the **executor**, because Universal Router executes calldata computed off-chain and any wallet or meta-aggregator can call it. The executor population fragments to 397 distinct senders by late 2025 with a hand registry capturing 11.8% of swaps. Maury (Zenodo 21513263) argues no standard on-chain mechanism announces frontend identity and supplies four recovery heuristics; Xi and Moallemi's own labelling reaches roughly 21% of transactions and 5.6% of volume on a single pair. Any executor attribution must be built by trace classification with an address-version registry, and stated as partial.

**What is genuinely open.** The intermediary-asset margin, multi-hop routing, and matched-trade head-to-head comparison are unoccupied. Separately, **nothing in the literature connects DEX routing to the vehicle-currency question at all**: searches for vehicle currency plus DeFi routing return zero. The framing is the contribution, and the multi-hop intermediary margin is promoted from incidental to central.

**Where incumbency can live.** Stickiness can reside in (i) **LP capital allocation**, since providers face switching costs, gas costs and attention limits, and (ii) **routing-system scope and defaults**, business and software decisions updated on a slower cadence than individual quotes. A router choosing the native asset because its pools are deepest may be mechanically optimal at that instant, while the reason those pools are deepest may be historical incumbency. Likewise, a restricted venue set or default path can persist even when the inner optimiser is deterministic. These are state variables to measure, not evidence of trader habit at quote time.

**Structural breaks are the identification spine.** This is the most consequential correction. The FX literature's decisive gap is that an incumbent's cost advantage is itself a consequence of its incumbency, so the data never contain the state in which a currency holds the vehicle role while being strictly cost-dominated by a rival. Gas-regime shifts, fee-tier introductions, protocol-version migrations and the March 2023 depeg are candidate windows in which exactly that state occurs on-chain. Earlier drafts listed these as regime controls to absorb. They are the variation to exploit.

**Condition reopened 2026-08-10.** See `docs/finding-cost-dominance-measured.md`. Strict pre-transaction V2-family state and gross route comparisons remain construction evidence, but all earlier all-in figures are withdrawn. The rebuilt dependency graph releases the gross route panel first, fetches the realised transaction's exact receipt gas price and gas used by transaction and block, and only then attaches receipt-calibrated route gas units. The retired daily gas pipeline and its artefacts are absent from the repository.

**On mechanical results, per Java: keep them, demote them.** Architectural factors (pair availability, pool existence, netting) shape dominance and belong in the paper as the layer that sets the feasible set, with slower allocative choices selecting within it. They may not lead, because a result whose sign is guaranteed by construction fails as a contribution.

### 4.2 Measurement requirements

Non-negotiable, because getting these wrong invalidates everything above. Adopt named methodology, which also buys referee familiarity.

- **Route cost: build a three-benchmark ladder ourselves.** The construction is standard optimisation and nobody's proprietary contribution, and Angeris, Chitra, Evans and Boyd (published) supply the theoretical warrant that gas-aware optimal routing is mixed-integer convex, so production routers are necessarily heuristic and a measurable shortfall exists. Suboptimality as proportional shortfall of the realised route against benchmarks solved at fixed pool state: support-constrained (reoptimise splits only across pools the trade touched, isolating mis-splitting), full-venue (reoptimise across all pools without gas, adding venue omission), and gas-aware full-venue (fixed per-pool activation cost, mixed-integer). Use a direction-asymmetric gas model, since one swap direction deducts from output while the other shrinks the input budget. Report medians alongside means, because a few per cent of trades drive the entire mean.
- **Cost level: adopt Barbon and Ranaldo's definition** of total cost as slippage plus fee plus gas over notional, on hypothetical trades at a fixed notional grid, hourly, with gas as a unit count times median gas price. Their headline: validator gas dominates trader cost, ahead of classical price impact.
- **Separate incidence, route-quality magnitude and economic-loss magnitude.** Dominance incidence and route-quality improvement compare two quantities of the same output token and therefore require no external token-price estimate. The price-free ratio is primary on the full route universe. Economic loss still converts both outputs to one value unit and divides their difference by input notional, but only on explicit input/output valuation-coherence support. Thin-token daily marks can value realised output at tens or hundreds of times marked input and manufacture enormous input-normalised basis-point magnitudes without changing which route returns more. Every incidence estimator must export the representative dollar magnitude, aggregate on admissible support, concentration in the upper tail, and a size distribution from the same sample. A frequent $8 friction and a rare $8,000 loss are different findings even when their incidence matches. Report each object under its own name; none substitutes for another.
- **Depth: realised all-in cost at fixed notionals is primary; marginal-price displacement is a secondary structural descriptor.** The earlier plan to define depth as dollars to move the marginal price 10 and 50 bps then "aggregate" across venues was wrong twice over. Marginal-price displacement and realised average execution cost stand in a design-dependent relation (roughly a factor of two in constant product for small trades, different entirely for stableswap's flat-then-convex curve and for concentrated liquidity's tick-dependent piecewise shape, where large marginal depth can coexist with a costly range exit). And the economically correct aggregation across heterogeneous pools is the joint split optimisation, and a sum of per-venue depth numbers has no economic meaning. There is no accepted academic depth standard; our own SoK (Xu, Paruch, Cousaert and Feng, ACM CSUR) is the natural citation for design-specific slippage and is checkable locally since we are an author.
- **Gas units, gas prices and monetary marks have separate owners and matching clocks.** A two-hop vehicle route is mechanically more gas-expensive than one hop, so omitting gas biases the comparison toward the vehicle route and makes gross direct-dominance incidence a lower bound. The realised transaction's paid gas is its receipt `gasUsed` times `effectiveGasPrice`, an exact transaction-level wei charge. Counterfactual route units come from a deterministic receipt sample conditioned on topology, venue sequence, year and intermediary type; transaction-level medians and interquartile ranges are primary because the realised receipt cannot reveal gas use for the route not taken and router bookkeeping remains inside receipt gas. The analytical gas price is the realised transaction receipt's `effectiveGasPrice`, joined by exact transaction hash and block number and applied to both counterfactual alternatives. An exact zero price is unsupported because private or bundle payment may sit outside the receipt. Same-block `baseFeePerGas` is the urgency-free sensitivity and remains explicitly unsupported before EIP-1559. Converting the exact wei charge to dollars or basis points is a separate valuation step: it must reuse the canonical independently sourced intraday WETH/USD panel, joined backward to the latest observation strictly before the target transaction. A daily WETH/USD mark may be reported only as a labeled sensitivity and cannot release a transaction-level all-in result. Whenever the underlying actions are transactions, including LP mints, burns, collects, and linked rebalances, cost is measured from exact receipts before aggregation to an hour, day, pool, or provider. No daily gas panel is retained. Receipt and block-header caches live under the shared Git runtime directory; deterministic snapshots must retain and reopen the exact RPC request, exact response, response digest, sanitized winning endpoint and full attempt history, then match every copied field back to that response. One validated transaction/block/hash panel forms the released generation. Any unresolved receipt, missing requested header, unverifiable transport record or receipt-to-header hash mismatch prevents that generation from being written.
- **Separate MEV from routing shortfall.** Realised amounts embed sandwich losses while simulated counterfactuals do not, so flag sandwiched trades and report cost both ways. Do not condition naively on submission channel: a large share of sandwich victims migrate to private RPC within weeks, which makes channel an endogenously selected treatment and disqualifies it as a control.
- **Intent venues need separate treatment.** Batch-auction and RFQ settlements may be internalised against solver inventory, in which case no AMM counterfactual describes the user's alternative. Treat batch venues as a structurally different cost regime, and do not assume solver competition passes value through, since more solver entry can reduce welfare.
- **Symmetric split treatment.** Comparing an unsplit best-single-pool direct route against a realised split vehicle route is not like-for-like.
- **Transaction-time state.** Transactions earlier in a block move reserves and ticks; report the wedge if daily state is used anywhere.
- **Sign the venue exclusions.** Under full-venue logic an omitted venue mechanically flatters whichever route depends on covered venues, so state the direction of the bias as well as its share.
- **Endogeneity, answered where it can be.** Whether an asset becomes the vehicle because costs are low or costs are low because vehicle liquidity accumulated is answered by cost-dominance windows and cross-venue spillover. The cross-aggregator cross-section cannot answer it, since a snapshot of routers contains no variation in incumbency holding cost fixed.
- **Self-returning, wash and arbitrage screens before any regression.** Canonical endpoint round-trip exclusion is already implemented and mandatory because those routes are outside the endpoint-conversion unit: they run 12.7% of multi-leg routes by count and 21.7% by value on the median of 79 sampled days, reaching 25.9% and 91.3% on 2025-12-06, the worst. This operational rule does not classify every excluded route as wash trading or arbitrage. The turnover-spike and volume-spike screens, explicit arbitrage-cycle detection and organic-versus-MEV decomposition in the reference repo's `ddc.integrity` still need applying separately.

### 4.3 Verification gaps to close before the framing locks

- **Flandreau and Jobst: CLOSED 2026-08-06, read first-hand.** Verified in `literature/text/2009-FlandreauJobst2009Empirics-*.txt`, and every claim the paper makes about them holds.

  - The degree-statistic characterisation is right. Their currency-status variable is literally *"Number of Markets Where Given Countries' Currencies are Traded"* (Table 1 heading), so it counts quoting markets and is silent on how much trade routes through a currency, which is what our differentiation sentence asserts.

**Two things the read surfaced that were NOT known before.**

*Citation version, needs a decision.* The bib entry `FlandreauJobst2006Empirics` is the CEPR Discussion Paper 5529 (2006), so the paper renders "Flandreau and Jobst (2006)". The deck's reference slide says "Flandreau and Jobst (2009), *The Economic Journal*". These disagree in a shipped deliverable. The published article is EJ 119(537), 2009. Cite the 2009 EJ article and re-verify that Table 3 column III carries the same 0.463 there, since the provenance comment currently points at the discussion paper's table.

*An interpretive bridge the paper does not currently make.* F&J's persistence regime is not just "slow"; they describe it as a state in which *"the country has higher interest rates and lower popularity than is warranted by the long-run equilibrium"*, with formerly minor powers experiencing *"a delayed rise to monetary leadership"*. That is the challenger's delayed rise. This paper measures the mirror image, the incumbent's delayed fall, and it can condition on the cost state where they cannot. The two are the same adjustment process observed from opposite ends, which is a sharper relation than "closest empirical precedent" and is worth one sentence in the introduction.

*The number reconciles, and HOW it reconciles is a warning.* 0.463 = 0.89 x 0.52, matching the γ1 and γ2 that F&J state in their own prose for column III. The table extraction is column-scrambled by the PDF reader, so **a number read out of an extracted table in `literature/text/` is not verified**, and only the surrounding prose is. The paper's provenance comment currently reads "Table 3 column III", which points at the one representation that cannot be trusted. Point it at section IV.A, where F&J state the product in words, and re-verify against the published EJ table before submission.

**Do NOT map θ onto γ1γ2 numerically.** They are not on the same scale: γ1γ2 is a long-run structural product from a two-equation feedback system, θ is a one-day-horizon hazard ratio. The honest statement is that both address whether the system returns to cost-efficiency, that F&J answer "it converges, slowly" from quotation counts with no counterfactual, and that this paper answers the same question with the declined route priced. Any stronger equivalence would be the kind of unearned bridge this section exists to prevent. **Novelty sweeps are OFF. Standing decision by Java, 2026-08-06, and it overrides the three gaps that used to sit here.**

Novelty is overrated and no result gets binned because someone else may have reached it. Corroborating an existing claim on better data is a contribution, and this paper's data prices the road not taken, which is the thing the FX literature cannot do whoever else has tried. A result stands or falls on whether it is measured correctly here.

Three former "gaps" are struck, and they were all novelty policing rather than accuracy:
- A working-paper sweep, SSRN or otherwise. Working papers are not a bar this paper has to clear, nothing here may depend on one, and reading a pile of them before forming a view is how a project inherits someone else's framing. Do NOT run one, and do not raise it again, unless Java explicitly asks.
- Chu, Dowling and Li on impermanent loss, previously flagged as the paper most likely to pre-empt the rent-incidence cross-section. If the rent result is right it is right, and if we do not cite them there is nothing to verify.
- The untraced MetaMask multi-aggregator study, flagged for the same reason.

**What survives, because it is a different obligation.** Any source this paper CITES and CHARACTERISES must be read first-hand and the characterisation checked. That is accuracy and not novelty, and it is where the real risk lives: a mis-stated precedent is a referee's first target, and it is the failure this project has actually had. Verify what we say about what we cite. Do not go looking for who else got there first.

**First check under the accuracy framing found a real error, 2026-08-06.** The load-bearing LVR closed form in the rent-incidence design was cited to `MilionisMoallemiRoughgarden2023Myersonian`, "A Myersonian Framework for Optimal Liquidity Provision in Automated Market Makers". The 19-page published article contains zero occurrences of "rebalanc", "loss-versus" or "impermanent"; it is about Bayesian updating, no-trade gaps and the bid-ask spread under asymmetric information. The result actually comes from Milionis, Moallemi, Roughgarden and Zhang, "Automated Market Making and Loss-Versus-Rebalancing" (arXiv 2208.06046), a different paper with the same three lead authors, which is exactly why it was confusable. The citation was corrected in the rent-incidence design, the mechanism provenance comment and the bibliography.

The formula itself is right: instantaneous LVR of one eighth of the variance rate times pool value is standard for the constant-product invariant. The later scientific audit nevertheless retired the old rent-incidence magnitudes because their variance came from each pool's own marginal-price path rather than an independent external reference price. The citation correction and the later estimand correction are separate: the first fixed attribution, while the second changed which empirical input can support the formula.

The lesson generalises. The exposure was never that somebody else had reached the result first; it was that the paper said something false about a source it leans on, in a paper whose whole substitute for identification is a validation apparatus. Check what we assert about what we cite, especially where several papers share authors.

Independence is the point. Form the reading from our own measurement, then check the sources we lean on.

**Parallel literature work is paper-grained.** Independent paper families may be discovered, downloaded and audited concurrently. One owner keeps a paper's published article, appendices, supplements, corrections, replication artifacts, full reading and claim adjudication in one sequential chain because companion evidence can reverse the main text's apparent result. Workers use isolated staging directories and manifests and do not edit the shared ledger. One reconciler verifies versions and hashes, removes superseded artifacts, writes the source-set record and closes the card. Never split one paper across concurrent readers merely to increase throughput.

**The literature gate binds evidence to the live manuscript.** `literature/use-contracts.json` is the single executable registry for adjudicated citation-use boundaries and vocabulary rules; `scripts/audit_findings_freeze.py` is the sole gate owner. Each claim-use rule points to the evidence-card field that establishes the boundary, then checks only paragraphs that cite that source. This is a deterministic guard against known semantic conflicts, not an automated substitute for reading: a newly discovered conflict becomes a reviewed contract before the card closes. Vocabulary absence has a different rule from methodology. A configured term is barred when it appears in the manuscript, appears in zero documents across the declared finance/economics corpus and the coverage floor passes. The absence of a method or measure never bars it; only an explicit source prohibition can do that. Main and companion extracts are search aids, not source artifacts. Every required PDF must be locally present and match the tracked checksum. An unavailable appendix keeps the source set and any card calling it complete open, while an explicitly embedded appendix closes only through the checksum-verified main PDF.

## 5. Method discipline adopted from documented practice (node F)

Sourced from an R&D pass over reproducibility and specification-robustness practice; full sourcing in the agent output.

- **Delete-and-rebuild as the gate** (Gentzkow and Shapiro). A run is done when a fresh clone regenerates every number, table and figure with no manual steps. That is the definition of done.
- **Machine-readable decision registry.** Every analytical choice is declared as a named parameter with alternatives enumerated in `docs/specification-lock.json`. The lock hashes its canonical content and the findings audit recomputes the hash, rejects duplicate claim IDs, and requires every entered claim to state its dependent variable, transformation, outlier rule, inference, alternatives, falsifier, interpretation bounds, inputs and outputs. Mitton (RFS 2022) showed that with discretion over ten routine choices a researcher can report over 70% of *randomly generated* variables as significant determinants of leverage; the three choices that matter most are dependent variable, transformation, and outlier treatment, so those are mandatory-to-vary.
- **Specification curves where discretion is load-bearing** (Simonsohn, Simmons and Nelson). A formal curve is required when several economically plausible choices materially move a headline conclusion; otherwise a compact, economically curated sensitivity table is sufficient. The dashboard shows which choices drive a result and uses joint inference where the family is coherent. A padded combinatorial multiverse deflates visible dispersion.
- **Claim-specific attack sets, not one universal robustness menu.** Each promoted claim names the strongest rival explanation and the measured object's main vulnerabilities, then runs the applicable influence, concentration, timing, selection and measurement attacks. Additional controls, placebos, stress splits, leave-one-out checks and reversals enter when they answer that claim's economics. A generic maximal battery can be simultaneously expensive and uninformative.
- **Small-cluster inference is not certified by CR1 alone.** Report the number and leverage of independent assignment or shock clusters and the effective degrees of freedom. Roughly 30–50 clusters is a review zone, not a magic cutoff; when asymptotic approximation is questionable, use wild-cluster/bootstrap, randomization-style inference or aggregation to the treatment level where feasible. A conventional clustered standard error with 20 clusters cannot by itself promote a headline.
- **Multiplicity follows the claim family.** Apply Holm or another declared adjustment to a coherent family of simultaneous headline claims. Do not combine construction diagnostics, falsifiers, robustness checks and unrelated outcomes into one artificial family; publish the family definition and retain unadjusted estimates for interpretation.
- **Selection adjustment follows the target population.** A conditional common-support result does not require IPW. Reweight only when the paper seeks a parent-population estimand and can defend selection on predetermined observables, positive selection probability across the target support and tolerable weight concentration. Report propensity overlap, stabilized and truncated weight tails and effective sample size. Structural absence of a route alternative violates positivity; IPW cannot manufacture that counterfactual, so bounded conditional framing plus included-versus-excluded diagnostics is stronger.
- **Multi-agent replication as a bug detector only.** Demoted after the independent review, correctly: Menkveld et al.'s 164 human teams measured genuine researcher variation, whereas N LLM agents on one codebase measure code-generation noise. Presenting that to a journal as an econometric quantity would be process theatre. Retained internal use: run the estimate independently twice with separate contexts, and treat any disagreement as evidence that one run has a bug. Menkveld et al.'s finding that dispersion falls after peer feedback still justifies putting the critique round before estimates are fixed.
- **Specification lock plus deviation log**, replacing external pre-registration, and placed **after** an explicit exploratory phase. The review objected to the friction; the exploratory-first ordering answers that, since distributions, pool anomalies, and contract mechanics must be understood before specifications are fixed. Burlig (2018) shows PAPs carry no epistemic credit for archival data, so this claims none: it is an internal integrity device, needed because version 1 did silently reframe results after seeing them. Keep the audit trail, decline the binding commitment.
- **Record everything run** (Harvey, JF 2017). Every fit enters the complete internal model ledger, including nulls and failures. The paper appendix contains every registered confirmatory fit, deviation, failure and exploration that changes a claim; minor development probes remain discoverable in the ledger without turning the appendix into an unreadable execution log. The drafting agent may not silently select.
- **Time means calendar time after support balancing.** A HAC estimator over filtered observations must receive the actual date index. Unsupported gaps contribute no autocovariance pair; the row after June 30 is not treated as one day away from January 1 merely because July through December were removed. Every balanced endpoint-year exhibit records this contract in its output.
- **Observation clocks and fixed-effect clocks are separate design axes.** Transaction, block and event records remain native upstream, while each estimator declares the observation clock at which its numerators and denominators are constructed and the fixed-effect clock used to absorb common conditions. Daily panel observations with date fixed effects are the primary cross-sectional design when each date contains multiple economic units. Daily observations with week and day-of-week fixed effects are a sensitivity that retains within-week movement, but any apparent precision gain must survive common-shock controls and correctly clustered inference. A weekly panel is a separate low-frequency robustness: it sums raw numerators and denominators inside complete non-overlapping seven-day UTC bins before constructing shares, ratios or returns, and it reports all seven possible anchor offsets because a continuous market gives no weekday a privileged boundary. Rolling windows may date transitions or smooth plots but do not enter ordinary inference unless overlap is handled explicitly. A single market-wide series cannot include a fixed effect at its own observation clock and instead uses calendar-aware HAC inference; the transaction-level records remain available for route-, token-, pair- and category-level panels with time fixed effects. A result that exists only daily is treated as a possible high-frequency or noise-sensitive effect; a result that exists only weekly requires an aggregation or slow-adjustment interpretation.
- **Method selection follows the estimand, never a battery.** Before a fit enters E0 or E1, its model-ledger record names the estimand, economic unit or duration risk set, identifying variation, dependence and inference, falsifier, current support state, and intended paper, deck, appendix or diagnostic destination. A method is not evidence merely because the code can run it, and changing the estimator does not repair an unidentified comparison. The live claim record in `docs/specification-lock.json` supplies the exact variables, alternatives and multiplicity family; the compact map below governs which estimator family can express them without changing the question.

- **Desk-reject filter, early.** JoF desk-rejects 43% before review. Before any polishing, one agent answers: what is the single novel contribution, and is it visibly large enough in the first two pages? A negative kills or reframes.
- **Rank-ordered internal referee** (Berk, Harvey and Hirshleifer): output must separate fatal from major from minor, every objection carrying a scientific argument. Undifferentiated flaw lists are penalised, since that is the failure mode LLM reviewers default to and the exact pathology the paper warns human referees against.

## 6. The graph

The graph is a dependency DAG with bounded feedback, not a sequence of agents. Nodes define scientific work; joins define when another workstream may consume it.

Node labels are instantiated per claim packet. Route composition may be at J1 while a V3 route-cost mechanism remains at D2 and a liquidity-provision idea remains at C; no global node color rewinds the completed packet or hides the others.

```text
 A venue and talk benchmark ----\
                                  -> C estimand and measurement <-> K ideation
 B domain literature -----------/             |
                                                v
                                      D1 -> D2 -> D3
                                                |
                                   J0 purpose-bound data release
                                                |
                                                v
                                      E0 exploration and rivals
                                        |                 |
                                        |                 +--> H visual/case-study backlog
                                        + - - provisional - - > P0/H working deliverables
                                        v
                                  E1 claim-specific lock
                                        |
                                        v
                                 F registered empirics
                                        |
                              J1 admitted finding packet
                                  /                 \
                       G/P0 working paper          H live deck
                                  \                 /
                         J2-paper / J2-deck certificates
                                        |
                             I independent challenge
                                        |
                         J3 submission freeze or return
```

**Join definitions.** J0 is scoped to one estimand. A released route-composition panel can support route-composition science while an unrelated exact-state mechanism panel remains under construction. A reproducible E0 packet may enter P0 or H through the dashed provisional edge so the working paper and deck stay self-contained and reviewable; its source comments and manifests carry the status, and it cannot enter J2 or J3. J1 contains the estimand, unit, comparison set, generation, coefficient or descriptive magnitude, one primary inference convention, sensitivity results, nulls, strongest rival explanation and admissible claim language. J2-paper and J2-deck independently certify each current deliverable from the same admitted J1 packets; one may pass while the other remains open. Their common-claim reconciliation feeds I. J3 requires a complete argument, current evidence, reproducibility, whole-deliverable language and visual review, and no material objection after the final integrative edit and independent challenge.

**Parallel work packages.** The coordinator issues a bounded brief naming the node, immutable inputs, output paths, allowed claim, tests, stop rule and downstream join. One writer owns each file or generated artefact. Methods, prose sections, slide assets and review can run concurrently only when their input and write sets are disjoint. Reviewers are read-only; the original builder answers their objections. The coordinator integrates completed packages and is the only owner of cross-package claim consistency. A finished package does not silently start adjacent work; the coordinator immediately schedules the next ready package or records the dependency that leaves no package ready.

**Interjections do not cancel compatible work.** A new comment is routed to the affected workstream while every non-conflicting package continues. A contradiction pauses only descendants of the disputed object. A reusable correction closes in two places: the immediate instance and the narrow preflight, test or workflow rule that prevents recurrence. Existing compatible requirements remain binding until Java explicitly withdraws them. Before adding an artefact or rule, the owner searches for the current owner, folds in durable content and deletes a superseded duplicate.

**Method breadth is an audit, not a fishing expedition.** E0 evaluates OLS/WLS, panel fixed effects, grouped binary models, duration models, exposure or event designs, assignment-level mean comparisons and distributional tests whenever the data could support them. F runs the families that match the estimand and risk set, records informative nulls and explains why invalid families were rejected. A method is never fitted merely to obtain significance. Published finance practice calibrates the design and claim; it does not turn a global architecture launch or endogenous adoption into causal variation.

**Paper and deck remain live.** G/P0 writes in the target-field register from the beginning. P1 is a final integrative edit before the last J2-paper, I and J3 pass, not a second manuscript or a ground-up rewrite. H is not derived mechanically from G: paper and deck share J1 evidence, while each keeps its own rhetorical and visual register. A deck review may expose a missing scientific comparison, and a paper review may expose a missing visual, but neither can change a finding without reopening E1 or F.

**Reopening and stopping.** C reopens only when a new idea, result or review exposes a definitional problem. D reopens only when a named estimand needs an unavailable input or a material defect can change the sample, magnitude, mechanism or inference. E1 or F reopens when a claim changes. One builder pass and one independent challenge normally close a package; another round needs a new material contradiction. The project is operationally complete when J3 passes for the paper, deck, replication package and submission files. Publication probability and future scientific revisions are not completion criteria that a workflow can guarantee.

Literature work remains active at the point of use. B is complete as a source base, but a methods package, prose passage, analogy, exhibit note or claim must reopen the closest raw sources and record how their design or rhetorical move appears in the final deliverable. Additional notes that do not change a design, claim, citation or deliverable do not count as progress.
