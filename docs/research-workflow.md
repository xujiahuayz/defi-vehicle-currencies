# Research workflow: paper and talk on dominant vehicle currencies

Version 3, 2026-08-08. Replaces `docs/nbc-2026-deck-pipeline.md` (version 1), whose single-venue empirics and deck were both binned. This is a graph. The paper and the deck inform each other, and evidence can send work back to design.

Every claim in the "grounding" column below was measured or read in this project. Where something is an assumption, it says so.

## 0. Standing rules

**Portability.** This file and every node's output is a plain tracked file in this repo. No node's real state may live only inside one model's session. Whatever executes a node reads this file plus the previous node's committed output and continues.

**One runner owns the research environment.** Invoke scripts and tests through `./scripts/run`; individual entry points never mutate `sys.path`. The runner places the current worktree's `src` and repository root on the import path, suppresses script-directory shadowing, and may reuse the primary checkout's environment without importing its source. Reusable logic still belongs in `src/ddvc/`, while `scripts/` remains thin entry points. This is a correctness gate, not only style: an editable environment shared with a linked worktree otherwise imports the primary checkout silently and can validate code other than the code under review.

**Logical data identity survives worktrees.** Provenance and cache keys record the repository-relative lexical input path, even when that path is a symlink to a shared data tree; the fingerprint still traverses and identifies the target contents. Resolving the symlink target into an absolute host path makes identical inputs look different across linked worktrees, destroys valid resumable caches at merge time and writes machine-specific manifests. A generated cache may move to the corrected logical key only after its marker, schema, row-count and deterministic-sample contracts pass.

**Engine, cache and result fingerprints depend on semantics, not orchestration.** Source-record meanings live in one small dependency-free module. Fetch cadence, retries, metadata writing, command help, release-gate implementation and documentation do not own those meanings and are excluded from analytical result fingerprints. A code change invalidates a materialised engine, day cache or panel only when it can change its rows or quality contract. The release gate remains an executable precondition for every consumer but is not itself an input to the consumer's economic result. The global market-state ledger is the exception because its cross-venue causal-order audit is an output column, so that audit code is part of the ledger's provenance without entering the partition engine key. These boundaries are tested explicitly; tying an expensive transform to orchestration makes harmless operational edits trigger full rebuilds and is a provenance defect, not conservatism. When an old exact-byte cache key differs only because comments, formatting or docstrings changed, the refresh owner may create a relative alias to the recorded release only after the provenance verifier reconstructs the stamped bytes and proves semantic and input identity. It never copies the cache, replaces an existing path, aliases an executable change or restamps old output as new.

**An additive schema migration is a checked transform, not a claimed shortcut.** A prior canonical partition may seed a new engine only when its raw-input fingerprint still matches, the old schema version is exact, and the migration leaves every pre-existing economic field unchanged. The migration writes the new schema through the same atomic boundary, recomputes affected quality counts, and then compares early, middle, and late migrated days for every venue against fresh raw normalization with exact field values and exact quality markers. A changed amount, identity, timing rule, invariant, filter, or row interpretation requires raw rematerialization; migration is allowed only for newly explicit metadata whose value is fully determined by the already canonical row. The full independently generated calendar and provenance ledger still run after migration.

**Raw provider data stops at node D.** Raw JSONL is an immutable ingestion layer, not an empirical interface. Node D materialises and versions the canonical research inputs for each AMM family: directed swap legs and identities; constant-product reserve snapshots and ordered reserve events; concentrated-liquidity swap states and signed tick changes; StableSwap pool snapshots and calibration trades; and weighted-pool closing balances plus ordered swap/join/exit events. Source-specific aliases and schema variants are resolved once in that layer. Every canonical partition carries an explicit schema version, row and identity counts, causal-order coverage, duplicate/conflict counts, unsupported-state reasons, and an input-aware fingerprint. Canonical readers exclude `usable = false` rows by default; an audit must opt in to see quarantined rows. A partition passes when no incompatible payloads claim the same causal identity, not when support is 100%: missing snapshots, incomplete provider entities, nonstandard token mechanics and impossible states remain counted, quarantined and visible in the coverage ledger. Each experiment then locks a minimum support rule on top of the canonical integrity gate. The full-calendar integrity and coverage gates must clear before E locks a design or F runs an experiment. Downstream estimators, validators and quote builders consume only these canonical products. Reading raw rows downstream is allowed only for an ingestion audit or a named defect diagnosis, and such output is diagnostic evidence, never a finding. A new provider schema or missing field reopens D instead of growing another local parser inside an experiment.

**Node D finishes the data once before experiments begin.** D has three internal gates. D1 inventories every field required by the entered claim registry and every active consumer, fixes its canonical meaning, and freezes the family schemas before an expensive build starts. D2 materialises the entire locked research window from each venue's verified genesis through the common sample cutoff; an audit subset may exercise the code but never counts as a completed data layer. The route and quote-state contracts are separate because topology covers eight routed venues while exact counterfactual pricing covers six state-reconstructable venues. The directed-route layer has 2,332 calendar partitions and 12,802 launched venue-days; a day with zero swaps is a typed empty partition, not an absent date. The quote-state layer has 11,009 family-venue-days. Before migration or rekey, `fetch_raw_market_data.py coverage --strict` must pass the exact research perimeter; the command rejects a missing file, sidecar, row ledger or mismatched canonical source/filename identity, while ignoring the checkout-specific absolute prefix, and rekey independently refuses any absent currently required stream. D3 signs both full-calendar quality and support ledgers, then materialises analysis-ready panels from those canonical events and states. Every active D3 builder calls the shared `ddvc.data_release` gate before reading a day: it checks the exact independent perimeter, passing global ledger, engine identity, current raw fingerprint and current per-partition marker. Globbing whatever files happen to exist is not a release condition. Only released analysis panels enter E and F. The transaction-state branch has one explicit validation loop: D3-base builds its prerequisites, E runs a separately named 77-date construction audit, failure returns to D2, and success returns to D3 for the separately named full-daily frontier. The full-daily builder enforces that edge itself: it requires current audit-panel, rejection-ledger and support provenance; exact agreement with the current 77-date calendar; and at least 99% chosen-route reproduction before it can start. After scoring, the daily support ledger must independently cover the exact released calendar and pass the same reproduction threshold before any canonical daily artifact is assembled or stamped. Audit and daily replays share a bounded 180-day checkpoint cadence, so an interruption costs at most 179 replay days without storing one large checkpoint per audit date. The audit never stands in for the daily 1-, 7-, 30-, and 120-day analysis input. A partial family build, a raw-data spot check, or a validator run can send D1 or D2 back for repair, but none releases an estimator. Candidate measures from K do not force speculative columns into the current schema: once C and E admit a measure, its data requirements reopen D1 before that experiment runs.

**Certificates, not apparent maturity, advance the graph.** Every edge consumes a machine-readable certificate that identifies the exact upstream generation, scope, schema, code and inputs. An existing panel, table, manuscript section, green compile or recent commit does not imply that its node passed. A changed or failed ancestor makes every descendant certificate stale before any descendant runner starts, and a descendant in construction mode may write diagnostics only. Repair resumes from the nearest invalid ancestor and reuses only shards whose own certificates still verify; it does not restart unrelated branches or continue polishing a stale descendant. This is the preflight that must run before an expensive node, not an audit reconstructed after the node has already consumed days.

**A schema promise is not field availability.** Before an expensive materializer starts, D1 inspects real early, middle and late partitions and records non-null coverage for every load-bearing field. A synthetic fixture proves code behavior only; it cannot establish that a provider actually populated a field. A source field with zero or inadequate corpus coverage is removed from the contract before the build, then replaced by a separately validated canonical transform or left unsupported. The same preflight runs again when a provider generation changes. This rule was added after a V3 LP-flow fixture supplied `amountUSD` although all 5,806,382 real mint/burn rows had token amounts but zero provider USD values.

**Provider rows do not prove event-source completeness.** Every load-bearing event stream must reconcile exact block, transaction and log identities against an independent source on a predeclared calendar before its canonical generation can be released. The comparison covers counts, missing and extra identities, duplicates, event class and exact signed quantities where available; a synthetic fixture, non-null coverage or a successful pagination loop cannot clear it. Any observed provider omission returns D to source repair and requires an independently retrieved supplement for that entire affected event class unless a separately reported audit establishes a bounded scope. Downstream code never floors an impossible state or calls a mostly complete event ledger exact. For V2-family replay, one shared 77-date transaction-frontier calendar now binds Uniswap V2 and Sushi V2 Mint, Burn and Swap streams to independently fetched Ethereum logs with exact UTC block cuts, audited token decimals and zero-event rows. Its pool registry comes from each factory's complete on-chain PairCreated sequence, and each daily core-event fetch is global by topic with no address filter before registered pools are attributed to venues; Graph rows under audit never define their own audit perimeter. The global raw responses live once in marker-last, globally aligned 50-block chunks, matching the current provider's enforced maximum; completeness and event-order reconciliation read the same files, complete chunks are immutable, and provenance points to them by portable relative path without copies or hardlinks. The workflow DAG is structural market-state prerelease, audited token decimals, independent V2 certificate, then full market-state release; builders of certificate inputs never call the downstream full-release gate. A current zero-exception certificate is required by both the market-state release and findings-freeze gates. This rule was added after the Uniswap V3 Graph corpus omitted one of six Mints in the same on-chain transaction, producing a false negative pool inventory even after exact decimal conversion.

**Provider order is evidence, not an identity convention.** Ethereum receipt `logIndex` is block-global. If two different provider events claim one block-log position, do not widen the causal key with transaction hash or mutate the provider capture. Reconcile the complete affected provider block span against global topic-only Ethereum logs, matching exact transaction, pool, event class and quantities. The immutable provider files remain evidence; one hashed reconciliation generation records order overrides, collapsed provider duplicates, exact payload overrides, ignored zero-state events and exact-chain supplements for omitted state-changing events. A supplement enters canonical state only with canonical pool statics, exact base-unit decoding and independently retained block-timestamp evidence. An unmatched provider event, ambiguous match, missing static, unproved timestamp or unsupported payload difference keeps the partition red. The generation and all exact evidence enter the canonical state fingerprint. This affected-span repair does not substitute for the independently defined full-day completeness certificate.

**State admissibility and quote-validation admissibility are separate.** An independently verified event that changes reserves enters causal state even when its net token deltas do not describe an ordinary one-input, one-output trade. A V2 Swap can contain excess input on both sides; both-positive or one-sided net reserve movement is therefore an exact state update but cannot validate a standard constant-product quote or enter a realised execution-cost sample. Quarantining that event from state makes every later quote in the pool wrong. Canonical rows carry `usable` for state reconstruction and `quote_supported` for economic quote use, and no parser may collapse those flags into one screen.

**A runner has one data role.** An ingestion/materialisation runner may read raw provider records and write a versioned canonical partition or analysis-ready panel; it may not report a paper estimate. An estimator may read registered canonical inputs and write results; it may not parse provider records. The findings audit resolves active producers from the specification and model ledgers plus artifact provenance, so adding a claim or model automatically expands the raw-boundary scan. It also verifies every registered claim input exists with current provenance. Both full perimeters are generated independently of observed files: 12,802 directed-route venue-days across eight venues and 11,009 quote-state family-venue-days across six. A missing primary stream therefore creates a failed partition instead of removing its date from the denominator. Each unified route day carries an input-aware marker over its exact launched-venue swap partitions, output identity, exclusions, duplicates and conflicts. A raw repair invalidates that day mechanically. Partial route or state builds never publish or overwrite a cumulative global ledger.

**A construction release must re-derive its semantics.** Provenance, row counts and schema are necessary but do not establish that a large panel means what its columns claim. The release audit independently checks the economic-cell key, formula identities, availability flags, path and source lineage, canonical scientific scope, and quantities that should remain invariant when one input is repeated across alternatives. The route-cost release therefore fails if direct and indirect availability disagree with quoted output, signed cost cannot be reproduced from those outputs, a path lacks an admitted source/pool identity, a direct quote changes only because the candidate intermediary changes, realised support changes across quote size, or any date contains a duplicate economic cell.

**A quote grid selected on realised intermediation is not a market census.** The main route-cost generation prices the 200 most heavily intermediated directed pairs on each day because those are the economically relevant vehicle markets, but that selection can change mechanically with the outcome the paper explains. Its levels and within-cell comparisons are descriptive for that selected support. Time change beyond the daily selected mix requires two predeclared checks: hold fixed the top 200 directed pairs by aggregate intermediary volume over the first 365 released days and separately retain pairs present on at least 80% of released days in every full calendar year from 2021 through 2025, declaring the latter unsupported if fewer than 20 pairs qualify. These cohorts describe established or persistently active vehicle markets, not the market as a whole. Candidate, pair, hour, notional and date dependence also make row-i.i.d. t-statistics invalid no matter how many quote cells the panel contains; the construction summary reports support and distributions only, while inference aggregates or clusters at the predeclared economic assignment and calendar levels.

**Dependence follows every repeated economic dimension that can carry a common shock.** A pool-month panel is serially dependent within pool and cross-sectionally dependent within calendar month, so its primary covariance is two-way clustered by pool and month; either one-way covariance is a sensitivity, not the headline. A quote-cell panel repeats endpoint pairs, dates, hours, candidates and notionals, so inference must first aggregate to the estimand's unit or use the predeclared pair and date clustering. A large row count never substitutes for independent assignment units, and every Wald test uses the same admitted covariance as its component coefficients.

**Same-token counterfactuals have one output mark.** Rank realised and counterfactual routes in output-token units, which needs no external price. When gas or economic magnitude requires dollars, convert the difference between their output quantities with one common output-token mark. Never mark the counterfactual output with an external price while retaining a separately reconstructed USD value for the realised output: the mixed basis can reverse the route ordering. Keep reconstructed component USD flow as a validation object, and require the common mark to reconcile to it on every strict dollar-support arm.

**A validation tolerance must sit below the estimand's scale.** A high reproduction share does not validate basis-point effects when the pass band itself is 100 basis points. The transaction-state frontier separately re-quotes the realised first leg, the second leg at its observed input, and their composition; the route is rejected when the maximum absolute error exceeds 1 basis point, with nested 0.1- and 0.01-basis-point samples pre-registered on that same maximum. This prevents two leg errors from offsetting in the final path output. The prior generation's path-only check retained 99.94%, 99.86% and 99.68% at those cutoffs, so the replacement audit must establish the support retained by the stricter leg-level contract before estimation.

**Chosen-pool reproduction does not license a counterfactual pool.** A V2 hour whose end-of-hour reserves can be unwound but cannot be bridged exactly to the previous observed state may attempt same-size reproduction only for its identified realised pool. Passing the leg-level output gate admits the realised route as the baseline; the pool stays outside alternative-route enumeration. A V2 pool enters the public frontier only in hours that pass reserve continuity after all observed swaps, mints and burns are replayed.

**Chosen-state coverage, conditional reproduction and verified coverage are different objects.** Reproducing 99% of available chosen quotes says nothing about routes whose pre-transaction state could not be reconstructed, while quoting nearly every route says nothing about how many quotes pass the leg-level tolerance. Every frontier support ledger therefore reconciles eligible routes to available quotes, mismatches, verified routes and other terminal outcomes. Before any maturation fit, E requires verified coverage, $(\text{available}-\text{mismatched})/\text{eligible}$, of at least 80% in every 2021-2025 primary year and no more than a 10-percentage-point spread between the best- and worst-covered primary years. Failure writes support rows only and returns to E-to-D review. Venue-family selection remains a required diagnostic because a pooled pass cannot establish representativeness; rising state availability or validation success can otherwise look like improving routing efficiency.

**External-market support is positive and address-resolved.** A token enters a CEX-reference robustness sample only when a validated source resolves its exact contract address to an observed CEX pair and supplies dated price observations. Ticker equality alone is insufficient, and absence from a selected publication package never means unlisted. The current bounded registry reproduces the 43 exact Uniswap--Binance matches in Lehar and Parlour's published package after applying the authors' reserve/volume screen, downloaded-symbol intersection, densest-pool rule and two ticker-collision exclusions. Its 4,113 rows are a 1-in-10,000 minute audit sample from 2020-05 through 2022-12, so first and last observations define a conservative positive-support window only. It can bound the V2 rent result on observably cross-listed tokens over that interval; it cannot classify the long tail, support a full-sample listing control or turn unsupported dates into zeros.

**Pool capital, local depth, executable band depth and LVR scale are different canonical quantities.** A protocol-family layer materialises each quantity independently when its own contract is ready; it never fabricates a complete row by copying one field into another. `capital_usd_lagged` is deposited pool wealth at the exact prior calendar date, built from token balances or range inventories and valued with a separately validated price source. `local_depth_usd` is invariant-specific marginal curvature at the measured state. `band_depth_usd` is executable inventory inside a stated price band or notional. `lvr_scale_usd` is the contemporaneous invariant-specific wealth scale used by an admitted LVR formula. Full-range constant product creates identities among some of these objects, but those identities do not transfer to concentrated liquidity, StableSwap, weighted pools or hook-based pools. Return and APR estimators fail closed unless their denominator is finite positive lagged capital with non-depth provenance. Dollar LVR, price impact and routing capacity use the venue's declared invariant adapter; the presence of any field called liquidity or TVL licenses none of them. A provider TVL may become capital only after row-level reconciliation to separately valued holdings. That reconstruction, validation, exact-calendar lag and rejection ledger belong to node D; an estimator may filter the released validation status but may not parse raw provider rows, reprice balances, loosen reconciliation or promote a field locally. Uniswap V3 `tvlUSD` failed that audit and is quarantined. Its event-complete replay is an event-accounted pool inventory, not yet deposited LP capital: historical token balances validate custody, while exact protocol-fee claims must be removed before ownership is attributed to LPs. Direct transfers and rebases appear as custody discrepancies and are never silently assigned to LPs. A validation sample may bound the discrepancy but cannot promote an unsampled panel; promotion requires a row-level ownership-reconciled generation, separate valuation and an exact prior-calendar-day lag. A new protocol therefore reopens D1 until each requested quantity's source, construction, timing, callable materializer and validation sample pass.

**The liquidity contract is exhaustive over venue, pool family, state generation and quantity, and it fails closed at the row.** `ddvc.liquidity` owns the protocol-capability registry, and its venue perimeter must equal the canonical DEX source inventory exactly. Each pool-family entry gives deposited capital, local marginal depth, executable band depth, finite-size quote quality and LVR an independent state generation, exact `module:callable` materializer, validation rule and readiness flag. Every custody-based capital construction must separately establish the contract's token balance, the economic claimant and the pool attribution; custody is not ownership. The freeze gate resolves every ready materializer and rejects a module-name string, missing callable or venue-wide label. Every admitted output row carries its pool/invariant family, quantity kind, state generation, validation generation, state timestamp, failure reason, provenance and exact-lag status when applicable; every estimator declares the quantity it requires and the freeze gate checks that declaration against the row contract. Full-range constant product may use separately validated reconstructed reserve value as capital and its invariant for depth and LVR. Concentrated liquidity requires event-replayed or separately reconciled inventories with protocol-owned claims removed for capital, active virtual reserves for local depth and tick-path quotes for band depth; it cannot enter LVR or return inference until a path-integrated LVR adapter passes. Curve StableSwap, CryptoSwap and NG families do not inherit one another's adapters. Balancer weighted, stable, composable-stable, linear, boosted, Gyro and custom pools must be admitted separately through measured out-of-sample quote reproduction; vault balances determine capital only after internal pool tokens, wrappers and rate providers are resolved. V4 vanilla concentrated pools do not authorize hooked or dynamic-fee pools, and all V4 capital remains unapproved until singleton claims are attributed to pools. Fluid's trade-only source authorizes neither capital nor depth. A return denominator whose source, validation lineage, quantity type, family or exact prior-calendar-day status is not explicitly permitted raises an error even when the column is named TVL.

**Quote quality is not depth.** The ratio of output dollars to input dollars at one notional, $O(q)/q$, is `quote_quality(q)`: it combines price level, fees and average slippage. It cannot be named marginal depth or executable capacity. `local_depth_usd` is a derivative of the invariant at a state; `band_depth_usd` is the maximum input inside a prespecified impact band and direction. Every venue's quote adapter applies the same fee-inclusive own-price-impact support threshold, while protocol reversion caps are recorded as additional constraints. Scaling balances must scale capital and band depth without changing marginal price; changing a V3 range, Curve amplification or Balancer weight at fixed holdings may change depth but cannot mechanically change capital. Provider TVL must reconcile to independently valued holdings on a validation sample or remain quarantined. Calibration trades and validation trades are disjoint.

**LP supply flows are built before they are estimated.** An estimator never parses provider rows, reconstructs prices, or classifies ranges locally. Node D orders canonical swaps and liquidity events exactly, classifies a range against the latest strictly prior swap state with `lower <= tick < upper`, records state age, and rejects events with no causal prior state. A V3 event is valued from its exact token amounts, a canonical address-day candidate price anchor and the exact prior `sqrtPriceX96`, with token decimals resolved by address; the nonexistent provider `amountUSD` field and symbol fallbacks are forbidden. Event value is allocated once across candidate sides, so a two-candidate pool never contributes its full value twice. When capital is unavailable, the released objects are dollar gross/net supply flows, within-day candidate shares and net-flow pressure only; their status explicitly says no capital-stock denominator, and they cannot be called flow rates, reallocation rates or returns. A normalized flow may be released later only against exact prior-calendar-day deposited capital over the same protocol perimeter, including pools with zero events. Daily end-state ticks, row shifts, cross-protocol denominators and event-level denominator repetition are prohibited. Mint and burn flows may be called liquidity supply flows or range placement. They may be called repositioning only after a validated controller identity links a burn to a subsequent mint within a stated time window; pool-level mint/burn totals do not establish that construct. The materializer writes accepted events, candidate allocations, candidate-days and a rejection ledger; the freeze gate checks valuation identity, event-value conservation, family/generation identity, causal time and the declared denominator status before any 1-, 7-, 30- or 120-day response is run.

**Construction mode cannot leak inference.** A runner that retains both panel construction and analysis for compatibility must expose `--panel-only` and return immediately after the provenance-stamped panel is installed. D3 invokes only that mode. It does not calculate HAC inference, print claim statistics, or write finding exhibits. E and F may invoke the analysis half only after the specification lock is current.

**Sync.** Commit and push after every completed node and at any other safe milestone. During continuous work, twelve hours is the absolute maximum between remote checkpoints. Long builds do not defer safe code-and-documentation checkpoints: exclude partial caches and stale generated manifests, label the commit as non-release when applicable, and keep the active process resumable. An unpushed completed node counts as unfinished.

**Distributed execution preserves one generation.** A second machine is a bounded worker, not another source of truth. Before it starts, fetch the same committed code, resolve the same scientific scope, record the input and engine fingerprints, and split only independent work whose output ownership is explicit. Do not migrate an advanced stateful run merely because another host is faster; let it finish while the second host takes a different ready queue. Raw or generated data crosses hosts through a staging directory, and nothing enters the live tree until the expected file perimeter and a deterministic content manifest pass. The manifest is format-aware: gzip identity is the ordered decompressed payload, since container bytes can vary across compression builds; ordinary byte-stable files use exact bytes; a binary analytical format needs an explicit schema-and-row canonicalizer before cross-environment equality may be claimed. `scripts/audit_portable_content_manifest.py` owns this check for the currently admitted gzip and byte-stable formats. When the cross-host link is slower than the provider route, the worker may fetch missing raw partitions directly, but it must then pass the same completeness, identity and chain-evidence gates before materialisation. A remote output is not complete until it is installed under the canonical generation, its provenance is current, and the source host's temporary copy is either retained as the named recovery checkpoint or removed after verification.

**Long jobs survive the transport session.** Any node expected to outlive an interactive check runs under a detached session manager or a supervised service on its execution host. The child process redirects stdout and stderr to a persistent node-specific log and writes exactly one atomic completion or failure marker from its exit status. SSH is used only to launch, inspect or resume that host-owned session; a live SSH socket, terminal tab or executor process is never the job owner. A vanished session with no marker is a failure requiring process and artifact verification, not evidence that work continues. Completion requires the marker, expected output perimeter and content/provenance validation.

**Live status is part of execution.** Every long node exposes its current graph node and return edge, resolved scope, completed and expected units, active worker and memory bounds, latest gate result, and any intermediate statistic that changes the scientific diagnosis. The driver reports those fields at material checkpoints while work continues; a temporary log or process identifier is not a user-facing status surface. `docs/findings-freeze.md` remains the durable scientific handoff, and it changes only when evidence changes, while runtime progress stays outside the paper and deck.

**Supersede means delete.** When a new version of any artefact exists, delete the old one in the same commit. Git history is the archive. Two live copies of a deck already caused a full review cycle to be spent on the wrong file.

**Challenge the spec itself, beyond conformance to it.** Every review node must answer: *is any requirement here wrong, unnecessary, or harmful to the deliverable's purpose?* A pipeline that only checks conformance will propagate a bad requirement to the deliverable. That is exactly how a slide reconciling the talk against its own submitted abstract survived three review phases: the requirement was written into the spec, so reviewers verified its presence instead of questioning its existence.

**Separate neighboring constructs before naming a finding.** A central term may not name two empirical objects. For this project, vehicle status is binary intermediary use, vehicle dominance is the continuous degree of that use, and cost domination or route regret is a separate comparison against an available alternative. The abstract asks what makes a vehicle currency dominant. Node C must write this semantic map into the specification lock, and the executable freeze audit must reject a lock that omits it. When an audit reveals conflation, reopen C and G; do not patch only the abstract.

**Conformance is a LOOP and never a step, and it closes every writing node.** `./scripts/run scripts/check_deliverable_conformance.py` runs the whole surface behind one command and exits non-zero on any failure: venue optics measured against the 14 published exemplars, prose conventions measured against the same corpus, house voice, provenance of every number, structural resemblance, spine agreement, and a clean compile of both the paper and the deck. It MUST run after ANY content change to either deliverable, and a node that changed content is not complete until it exits zero. `--brief` prints an agent brief naming exactly what is short, so the correction is dispatchable without anyone diagnosing it first.

The reason it is a loop is that content and conformance interfere. Every rewrite for content can break register, structure and resemblance again, and the failure mode this replaces is real: the paper was written, optics were measured once, an agent was dispatched by hand to fix what the measurement found, and the next content change silently undid part of it. A check that depends on someone remembering to dispatch it is not a check.

**Order nodes by the cost of redoing them, and freeze a node's input before running an expensive one.**

**Time design has three named axes.** Audit-date sampling chooses which observations receive an expensive transaction-state reconstruction; quote-state resolution chooses the instant used within each observation; response horizons define the elapsed time in a dynamic estimand. Record them separately in the specification and output schema. An individual day chosen from each calendar month is an audit sample, not a monthly aggregation or horizon. Dynamic horizons use exact elapsed calendar days because calendar months vary in length. Each horizon ladder has one canonical owner, and executable consumers import it instead of copying integer lists. Intraday horizons are added only when the mechanism can operate within a day and the underlying state and outcome timestamps are both precise enough to identify that response.

**A locked empirical execution spells out every scientific scope argument.** Script defaults are conveniences, not an estimand. Before launching a long build, reconstruct the prior release's arguments and notes, compare its dates, within-day states, horizons, candidate and venue perimeter, pair limit, trade sizes and support switches with the specification lock, then record the complete resolved execution. Worker count may change without changing scope; omitting an argument because its current default happens to agree may not. This rule was added after a queued route-cost rebuild would have used the script's one-hour default even though the locked design and prior release price all 24 hourly states.

**A daily chain-state cut comes from the chain clock, not a provider's last event.** Event-stream metadata such as `max_block` records the latest row observed in whichever stream produced the metadata; it is not necessarily the final block before UTC midnight, and a later mint, collection or donation may exist after it. A daily inventory or historical-balance audit therefore resolves the last block strictly before the next UTC midnight from primary-chain block timestamps, persists the raw request and block-hash/timestamp response, and proves that the next block is at or after the cut. The first or last observed swap, a stream-specific metadata maximum and a fixed blocks-per-day approximation are prohibited substitutes. Event fetches cover the resolved cut, while response horizons remain exact calendar-day links between those daily states.

**Expensive nodes have one executable owner.** A long build must acquire a non-blocking job lock before it reads or writes shared artifacts, record its process and command in that lock, and refuse an overlapping launch. Every final artifact is installed from a unique temporary sibling by atomic replacement; a fixed `.tmp` name is unsafe because two processes can truncate the same file before either replaces it. After an interruption, the workflow validates the artifact and its manifest before deciding whether to resume or recompute. Provider-response and deterministic candidate caches that are safe to reuse across branches live under the same Git-common runtime directory as their locks; a worktree-local cache must not force an identical refetch. The canonical implementation is `ddvc.runtime`, not a session note or an agent-specific convention. This rule was made executable after two V4 enrichment processes were found writing an overlapping date range on 2026-08-06.

**Raw mutation and canonical materialisation are one exclusion domain.** Fetch, sparse repair, static enrichment and market-state materialisation acquire the same cross-process raw-data lock. The lock lives under Git's common directory, so linked worktrees that share raw symlink targets also share one owner; a worktree-local lock does not protect shared data. Atomic replacement prevents partial files, but it does not make an overlapping read safe: a materialiser could read the old inode and fingerprint the newly installed path, falsely marking old content current. Disjoint-source parallelism is allowed only after the lock is partitioned mechanically by exact source; manual claims that two jobs touch different venues do not weaken the shared lock.

**A provider refetch or sparse correction is admitted by chain evidence, not by freshness.** Preserve the displaced capture, compare old and new rows on transaction, pool, token identities, timestamp and exact economic amounts, and receipt-audit every changed swap before releasing the raw repair. Event IDs and provider pagination positions do not establish economic identity. Convert human amounts to base units through the shared exact integer converter; default decimal-context multiplication can silently round high-significance token quantities. A repaired row must match receipt amounts and log index, while unresolved receipts or any mismatch keep D2 closed. Scan the complete canonical tick perimeter for block-log keys claimed by more than one venue too, including rows whose apparent economic payload did not change: an unchanged stale log index can collide with another transaction and is invisible to an economic-delta comparison. Prefer an exact provider entity that agrees across at least two live routes and matches the receipt. If that entity is no longer served, a sparse correction may instead use a byte-identical receipt from at least two independent RPC routes, but every changed field must be directly decoded from that receipt; preserve the displaced gzip under a content hash and record the RPC count, receipt digest and exact before/after payload in the day metadata. The global quality ledger repeats the cross-venue conflict count and D2 releases only at zero. `scripts/audit_v2_refetch_receipts.py` makes the V2 delta, collision, provider-consensus and receipt checks replayable with an incremental full-receipt cache.

**Provider-supplied immutable statics receive a full-history identity audit.** A field can be complete on every row and still contradict itself across dates. D2 groups the complete concentrated-liquidity perimeter by pool and compares token identities, token decimals, fee, tick spacing and hooks. Any pool with more than one static tuple enters a versioned, provenance-current quarantine panel before replay begins; every date for that pool is excluded, including dates before the conflicting row first appears. The replay seeds this complete exclusion set at initialization and also quarantines a newly observed conflict in memory as a secondary fail-closed guard. It must never quote a pool for early dates and discover only later that its statics were unstable. Raw provider captures remain unchanged unless chain evidence supports a field-level correction. The global quality ledger repeats the quarantine count, and downstream release fails if that count and the exclusion panel disagree. This rule was made executable after 29,005,863 V4 swaps contained only two pools with temporal static drift, both in token decimals: a sequential replay otherwise stopped when the first conflicting row arrived and could have admitted the pool on earlier dates.

**Shard expensive nodes by estimated work, not calendar length.** Equal-day chunks are badly unbalanced when later raw days are much larger: in the full route rebuild, the first three 285-day workers finished while five recent-era workers remained active, stranding three cores even though half of the latest chunk was still open. Estimate weight from input bytes or event counts, assign roughly equal total weight, and keep the day-level cache as the resumable unit. Dynamic work stealing is preferable when state can be checkpointed cheaply; when each worker carries a cumulative state index, weighted contiguous chunks preserve locality without equating one early day to one late day.

**One transient shard failure does not terminate a long independent queue.** A throttled or gateway-failed raw chunk is requeued at the tail while other independent chunks continue, with bounded per-chunk attempts and an explicit terminal-failure ledger. Only a deterministic payload defect fails the queue immediately. Completed chunks are atomic and validated before they count as cached; an interrupted run resumes from those chunks and checks for orphaned temporaries. Exhausting the bounded retry policy still fails the node, but a single temporary endpoint failure cannot discard hours of otherwise independent progress.

**Full panels assemble from shards out of core.** An expensive daily builder writes one atomically installed, generation-keyed shard at a time and retains only compact support metadata in memory. It never accumulates the full sample as a list of DataFrames. Final assembly is a separate rerunnable step owned by `ddvc.panel_assembly`: unify shard schemas, stream rows into a temporary Parquet file, enforce the economic-key uniqueness and support-row total, atomically replace the canonical panel, then stamp it. An assembly failure preserves both the complete shards and the prior canonical output.

Two classes of node, and the graph must not mix them up.

*Idempotent gates* cost nothing to re-run and carry no state: measurement, linting, conformance. They run continuously, after every change, and re-running them on unchanged input is free.

*Non-idempotent transforms* consume a settled input and produce an artefact that has to be regenerated in full when that input moves: the prose rewrite (node P), deck authoring (H), figure polish. Running one of these before its input freezes buys rework in direct proportion to how much the input still moves.

This was violated on 2026-08-06 and the cost was legible in advance. Node P was launched while the horse race still carried one account with *no completed test at all* and another whose *discriminating test is blocked by a measure*, and while section 5 of the paper itself ends "the ranking here moves when the six-venue panel returns its own". Section 5's prose was therefore scheduled to be rewritten twice before anyone had written it once. Three of the four verification gaps in section 4.3 were also still open, and two of them sit under results that lead the paper.

**FREEZE GATE on node P.** It does not start until all four hold:
1. Every claim that leads a section has a completed test, so no headline rests on "blocked" or "no completed test".
2. The durable literature ledger is complete: every source carrying scientific or venue-design weight has an individual full-text paper card, every cited characterisation resolves to an exact location in the saved source, and central scientific uses have an independent second read. Abstracts, search hits, extraction scripts, corpus counts and an agent transcript do not satisfy this gate.
3. Every open decision in section 8 is decided.
4. Two consecutive F <-> G passes generate no new claim and retire none.

**LITERATURE GATE on B, C, F, G and P.** Literature is evidence on five separately recorded axes: scientific contribution and evidentiary use; macro/micro structure; content depth; content breadth and boundary discipline; and optics/positioning, including title, opening, exhibit hierarchy, claim calibration and reviewer-facing credibility. Every load-bearing source and every venue exemplar is read in full as an individual paper; aggregate measurement is allowed only after the individual card exists. `docs/literature-audit.md` is the durable ledger and must link the exact source version, reading status, card, bibliography key and every manuscript use, with exact locations and an actionable implication for this paper on every axis. A published venue exemplar closes only from its published version; reading a working paper can advance the scientific card but cannot establish final structure or optics. A new citation, mechanism, design precedent or venue claim reopens B. A disagreement or attribution failure reopens the downstream node that used it.

**Admission precedes acquisition.** Before a candidate enters the bibliography or consumes a full-reading slot, screen its publication or institutional standing, author and field credibility, scholarly uptake, finance relevance, evidentiary role and technical sanity. Every source, including an apparent journal article, requires a complete decision in `literature/source-admission.json`; BibTeX type is only a consistency check and never admits a source. Peer-reviewed finance and economics work enters the scholarly lane. Adjacent-field proceedings and institutional working papers enter only when their role is material and explicit. Official protocol specifications may enter a separate primary-technical lane for contract mechanics, but cannot support economic behaviour, equilibrium, identification or venue norms. A primary-technical card may resolve to a versioned source note and integrity-checked code archive when no PDF is the authoritative artifact; the literature gate cannot force code-only evidence through a fake paper lane. Being recent or lightly cited is not independently disqualifying, but an arXiv-only source with weak field standing, negligible uptake, poor finance fit and technical defects is excluded before retrieval. Excluded candidates remain in the ledger so a later search cannot silently reintroduce them under a new key. Both acquisition routes and the findings-freeze audit call the same admission implementation. Source discovery verifies whether a preprint has since been published and updates stale bibliography types before interpretation begins.

**One clean-room reader owns one paper card.** Before dispatch, scan the full article for references to an online appendix, internet appendix, supplementary material, web appendix, data appendix, correction, corrigendum, disclosure, replication code or data package, then check the DOI landing page and an author or publication page for companion artifacts. Save and validate each textual companion under its own bibliography/source-map key; materialize and integrity-check every declared non-text package or preserve a source note that records its exact unavailable disposition. Dispatch `glotl review full-text-reader <saved-source> --venue jfe --out docs/reviews` with only the complete source and the exact manuscript attribution to verify; dispatch every textual companion separately, then inspect non-text inventories and reconcile the source set into one canonical paper card. The reader follows the portable `full-text-reader` charter and returns the required companions, scientific, structure, depth, breadth, optics, locations and implication fields. A central paper receives a second source-only dispatch that cannot see the first card; only after both records exist may the maintainer reconcile them into `docs/literature-audit.md`. Parallel readers may cover different papers, but no reader may replace full sequential reading with search or divide one paper into unowned fragments.

**Parallelise source sets, never fragments of one read.** Companion discovery, DOI/publisher checks, author/repository checks and retrieval may run concurrently across disjoint bibliography keys. Each source set has one named owner who reconciles those checks and records every discovered artifact before the set can close. At most one mutating fetch process owns a key, and acquisition still passes through the canonical deduplicating installer. The main article and every textual companion are then read sequentially as separate complete artifacts; concurrent discovery results cannot substitute for those reads. This is the default literature schedule because search latency is independent across source sets while interpretation is not.

**Source state is explicit and monotone.** A paper progresses through `temporary download -> validated main PDF plus validated companion set -> canonical literature files -> indexed text -> full-text reads -> reconciled durable card -> committed and pushed`. PDF magic is necessary but insufficient: the shared installer must match a title majority and every bibliography author surname inside the title-page window; a title match with only part of the byline is rejected. Image-only or secondary facsimiles require a durable source note, cryptographic hash, visual version check and OCR before use. A browser download is not saved merely because the browser lists it, and a source read from a temporary profile cannot advance the literature gate. Before reporting a source as saved or a reading as complete, validate each PDF signature and identity, persist the exact versions under `literature/papers/`, generate their page-delimited extracts and index entries, and point the card at the complete source set. If a correction or corrigendum is publisher-native HTML and its advertised PDF cannot be retrieved, preserve a canonical source note containing the official page, DOI, retrieval date, exact substantive correction and retrieval failure; this may close the substantive companion only when the official page contains the complete text and the card discloses that the typeset PDF is unavailable. Gitignored literature caches are worktree-local: a source acquired inside an isolated worktree must also be installed in the primary project clone and verified byte-identical before it is reported as visible to Java. The browser fetcher must consume a completed download before its context closes. Once the published article is available, remove weaker or wrong local versions and their text records after the validated replacement lands unless a version comparison is itself an explicit research object.

**Absence is an attribution boundary, not a methodological veto.** If a paper or even the full comparison corpus does not use a measure, that absence means the literature cannot be cited as evidence for the measure. It may instead be a novel research contribution, subject to the paper's own theory, construction, validation, identification and data-contract gates. A method or measure is prohibited only by an explicit impossibility argument, a failed design or data gate, or a recorded project decision. Vocabulary is the exception: usage across a sufficiently broad field or venue corpus is itself the object being measured, so corpus-wide absence can prohibit a term even when it says nothing against the underlying method.

**Incident status, 2026-08-07.** The old venue profile said all fourteen JFE exemplars were independently read but stored the detail only in agent output, while `docs/paper-spine.md` later described a nine-paper architecture corpus. Neither denominator resolved to durable paper cards, so the workflow could not establish which papers were read for substance, which for structure or optics, and which only entered aggregate scripts. Those claims are provisional until reconciled in the ledger. This is why a wrong LVR attribution survived: a text search eventually caught it, but the workflow had no paper-by-paper evidence gate.

**Research-state reconciliation is executable.** After every F to G pass, update `docs/findings-freeze.md` and run `./scripts/run scripts/audit_findings_freeze.py`. The audit checks the live artefacts, their input-aware provenance, panel coverage, retired estimands in the refresh graph, and the unchanged-pass counter. Commit order, document recency, and a green paper build are not evidence that findings are frozen. This gate was added after prose work began while the full panel manifest still described 18,120 rows, v4 was priced on 30 of its historical days, and the downstream refresher still ran estimands the definition audit had retired.

**One model ledger separates execution volume from admissible evidence.** `docs/model-ledger.json` is the canonical family-level inventory for fitted statistical models. Every family records its claim, estimator, fixed effects, inference, substantive and diagnostic specification counts, resampling refits, artefacts, and one of four statuses: `admissible`, `diagnostic`, `withheld`, or `retired`. A multivariate fit counts once, not once per coefficient; pretrend and pseudo-break fits are diagnostics; permutation, randomisation, and power-simulation fits are refits, not additional empirical specifications. The findings-freeze audit owns the ledger gate. Paper tables, old specification registries, and prose may consume the ledger but may not maintain a competing count.

**Audit calendars do not define economic horizons.** A transaction-state day sampled near the middle of each calendar month is an estimator-validation snapshot only. It can test causal ordering, quote reproduction, arithmetic, support, and failure concentration across the project span; it cannot establish persistence, a structural break, or a market-maturation trend. Final dynamic estimation uses daily exact-state observations and exact calendar-day links at 1, 7, 30, and 120 days. Calendar months and row shifts are prohibited substitutes because they change elapsed time when month length or observation density changes.

**Validation state must be causally timed.** Every validation claim records its type: same-implementation arithmetic, independent-implementation agreement, historical-state reconstruction, or transaction gas-feasibility. One type cannot silently license another. Reproducing a realised outcome is a valid quoter or simulator check only when every state variable contains information available immediately before that observation. Calendar-day membership is not enough, and block membership is not enough either. Replay all state-changing events by block and log index, use a strict-before lookup, and include a regression test with a state change between two observations. Both concentrated-liquidity validators once paired the preceding swap's price with the validation day's final liquidity map; this leaked later liquidity into earlier quotes. One shared event-order owner now interleaves V3 mints, V3 burns, V4 signed liquidity changes and swaps. Strict replay covers 1,206 V3 swaps and 4,218 V4 swaps, all inside 1%; V4's p99 absolute error is 0.00000039% and its maximum is 0.000998%. The first “own-block” triangle instrument then repeated the same class of error at a finer level: ordering only by block and using `bisect_right` included the target swap's own post-state and could include later logs from the same block. Strict block-log ordering raised the under-one-minute verdict-flip rate from 15.56% to 22.49%. Reverse state reconstruction has an additional contract: a timeline of per-event pre-states must return the first event at or after the target's pre-state, or the preceding event's post-state. Returning the last pre-state at or before the target omits the preceding swap's effect, while timestamp-only ordering also confounds events in the same second. A coherent unwind is not proof that all reserve changes are observed: replay swaps, mints and burns together, then require continuity against the nearest prior observed reserve advanced through every intervening raw event. An absent immediately preceding clock-hour observation is not itself a failure when the gap contains no unexplained state change; an absent prior state or a residual mismatch is unverifiable support and must be excluded. A validator also has to sample the estimand's population: direct-pool swap times are opportunity snapshots, not realised multi-leg routes, and whole transactions are not reconstructed route components, however precisely their state is ordered.

**Validation failures retain identities, not only counts.** Any validation rule that excludes an observation writes a rejection ledger with the same causal key as the admitted panel, the realised and reconstructed values, the signed error, the failure reason, and the strata needed to localise it by date, venue, pool, and asset. Aggregate failure rates supplement that ledger and never replace it. A pooled threshold cannot pass while the rejected observations are available only as a count, because a venue-era collapse, token migration, or unsupported transfer mechanic can then be hidden inside an acceptable average and cannot be bounded in the estimand.

**Canonical identifiers own aggregation; display labels never do.** Canonicalise machine keys before selecting endpoints, ranking pairs or grouping observations, enforce the expected key uniqueness on every generated shard and final panel, and attach human-readable labels only after aggregation. A display field is metadata and cannot be allowed to split an economic cell. This became an executable rule after native ETH and WETH were correctly unified at the address layer but the route-cost pair selector continued grouping on `ETH` and `WETH`. The result was 1,372,248 duplicated quote cells in the assembled panel, all with multiplicity two. The corrected selector aggregates only on canonical endpoint addresses, rejects components with non-unique canonical endpoints and chooses one deterministic label after the economic cell is fixed. The rebuilt panel contains 123,384,168 unique cells from all 2,277 day shards; deliberately assembling the superseded cache still triggers the duplicate-key refusal and atomically preserves the corrected output.

**Market maturation is a decomposition, not one trend.** A rise in cross-venue paths measures opportunity-set integration. A decline in realised-to-best cost gaps within a fixed reachable set measures search and pool selection. A decline relative to the best direct or alternative-vehicle path measures path and intermediary selection. A change in which currency intermediates routes measures vehicle-currency rotation. None stands in for another, and “the market became more efficient” is admissible only after the relevant margin is named. A routing technology can also move the extensive and composition margins in opposite directions: it may reduce indirect routing by finding direct liquidity while strengthening one intermediary among the routes that remain, or expand indirect routing by activating fragmented spokes. Pre-specify both margins instead of letting one technology story rationalise either sign after the fact. The routing-efficiency branch therefore reports integration, indirect-route incidence, within-vehicle search, path selection and vehicle choice as separate estimands before it asks whether they move together. Quote-size interpolation also has an identity contract: the winning intermediary, venue sequence and exact pool sequence must be unchanged at the bracketing sizes. If any of them switches, interpolating the two winners constructs a path that was never quoted and the cell is quarantined. Even a stable-path interpolation remains provisional until exact-size transaction-state re-quoting validates its error distribution. The benchmark decomposition is a validation and conditioning device, not a novelty claim: `docs/router-identification-feasibility.md` owns the prior-art boundary and records the binding Xi and Moallemi overlap.

**Topology, valuation and support are separate contracts.** Directed token flow determines whether a component is economic, which tokens are endpoints, whether it contains an intermediary, and whether multiple legs are a direct pool split or a sequential path. A leg-level dollar estimate may audit and weight that object, but it never defines the object. Count results use the topology-valid clean-leg perimeter; value results report raw weights plus nested source-to-intermediary-to-sink coherence bands. Every support label names its axis in the output schema. In particular, route-flow coherence and quote-grid notional proximity are two dimensions even when both happen to use 2x and 20% bands; a paper-facing restriction must state whether it applies to one or their intersection. This rule was made executable after multi-leg routes were found to include direct pool splits and a quote-size screen was described as valuation coherence.

**A fixed-cost calibration carries its own support hierarchy.** Route gas is measured from receipts on exact one-component transactions, first matched by year, leg count, venue sequence and intermediary. Missing exact cells fall back through named levels, and every applied estimate records the level, contributing cells and transactions. Broader levels aggregate prespecified cell medians instead of raw selected receipts, so a vehicle with more sampled transactions cannot acquire extra weight accidentally. The main estimate uses the matched median and reports an interquartile sensitivity; it does not call marginal quartiles a confidence interval. Total receipt gas includes router approvals, transfers and bookkeeping beyond AMM execution, which is part of the trader's realised cost but prevents interpreting the level as a pure per-hop technology parameter.

Until then, write to `memo/` freely. Discovery register is correct there, because a record is judged on whether it is complete and traceable and never on whether it reads like the venue.

**The transform must be a FUNCTION of its input, never an edit to it.** Node P writes `paper/` FROM `memo/` and leaves the memo untouched. That is what makes it re-runnable: when a finding changes, the affected section is regenerated rather than patched, and patching is the mode that was measured not to converge. Rewriting the memo in place would destroy the input and make the second run impossible.

**A gate that cannot pass yet must REPORT and not FAIL.** While `paper/` does not exist, the shape gate measures the memo and reports the distance the rewrite has to travel, which is useful. Wiring that distance into a red build would leave conformance permanently red, and a permanently red gate trains everyone to ignore it, which is how a real failure gets missed later.

**Conventions come from the corpus in BOTH directions, and one direction alone does not converge.**

*Subtractive half, already in place.* When a stylistic tell is suspected, it is added as a PROBE to `scripts/measure_prose_conventions.py`, and `scripts/find_prose_outliers.py` discovers tells nobody named first. Both report the draft's rate per thousand words beside the published corpus and flag only what no published paper reaches.

*Positive half, added 2026-08-06 because the subtractive half was measured to be insufficient.* `scripts/measure_venue_shape.py` measures what venue prose IS and reports target bands: sentence length and its long tail, commas, subordinate clauses, share of sentences carrying none, sentences per paragraph, heading grammar, heading STRUCTURE (subsections per section, and which sections carry none), and the share of sentences that open on information the previous sentence already carried.

The grounding is a measured failure. Forty-two clean deletions of a banned construction moved the discovered-tell count by a third and moved both gates by nothing, because deleting a tell never installs a convention. Three findings from that round:

- **The draft was lexically saturated.** Nearly every candidate replacement was already at or past its own corpus ceiling (`bound` -18 occurrences of headroom, `threshold` -19, `quote` -35, `reading` -28). A document with no vocabulary headroom has a sentence-architecture problem, and word substitution has nowhere to move.
- **Shape survives synonym substitution.** Rewriting "and not at economics" as "and never at economics" changed the word and kept the banned correction-by-negation shape exactly.
- **Over-correction is invisible to the subtractive gates.** A first pass on section 3 cut the median sentence from 26 words to 14 and the venue's long tail to zero. Every subtractive gate approved. Only the positive bands caught it.

*Both gates bind.* A section is done when it sits inside the shape bands AND clears the two discovery gates. Neither alone is sufficient, and the positive bands are aimed at the venue's interquartile range, never at zero.

*A target computed from a varying corpus is not a target.* `measure_venue_shape.py` treats an exemplar that fails to extract as FATAL. The first version swallowed timeouts, so bands were silently computed from twelve papers instead of fourteen and moved between runs on identical inputs, and a section measured against one run was judged against a different ruler on the next.

It remains true that the corpus uses em dashes, "rather than" and three-item lists freely, so those are venue conventions and any ban on them is an author preference that must be labelled as one and not confused with venue conformance.

**A reported comparison is not a result until it is estimated conditionally.** Raw rates, shares and differences identify nothing on their own, since composition, the number of candidates, calendar conditions and pair heterogeneity all move them. Every headline comparison carries a specification with fixed effects, controls and clustered standard errors, and `fixed_effects` and `std_errors` are measured features in the optics comparison for exactly this reason. The failure this prevents: a turnover hazard ratio of 1.17 was reported from unconditional pair-day rates before any absorption was applied.

**Independent review.** Reviews that matter use a clean-room specialist selected from a different executor family through the portable role interface (`glotl review <role> <artifact>`), with the authoring executor and private discussion withheld. Grounding: a nine-judge same-family panel was measured to carry the independent information of about two votes, because shared training produces shared blind spots and a judge inflates its score when it shares the mistake being judged. Same-family redundancy buys confidence without accuracy. The workflow contract names the review role and independence condition, never a provider, model or host-specific command flag.

**No internal process in any deliverable.** No slide or paragraph reconciles the work against its own earlier plans, renumbers propositions, references pipeline phases, or opens with limitations. Reporting a null is mandatory and belongs in results, stated as a finding. Performed uncertainty at the reader is a different thing and has no place there.

## 1. What the venue appears to require (node A output, literature audit reopened)

The existing profile reports results from a fourteen-paper JFE venue corpus, and the current paper spine reports a nine-paper architecture subset. The underlying PDFs and aggregate measurements survive, but “full detail in the agent output” does not. Treat every count below as provisional until its denominator resolves to completed full-text cards in `docs/literature-audit.md`; the audit must cover both scientific content and venue craft paper by paper.

**Invariants, to comply with:**
- No standalone literature-review section (14/14). The review sits inside the introduction, each strand closing with a differentiation sentence.
- Introduction 5.5–8 manuscript pages, 12–18% of the document, narrating the whole argument in prose before any notation, and previewing every finding.
- Six top-level sections, ±2. None of the 14 has five. Last section is the Conclusion (14/14).
- Abstract ~100 words (median 101, 11/14 within 96–106). Opens in first person with what the paper does. No gap-framing (0/14). No coefficients, t-statistics, sample periods or sizes (0/14). 10/14 contain no numbers at all.
- No H1/H2 hypothesis list (0/14). No testable-predictions exhibit (0/14).
- If there are numbered results: Propositions, not Theorems (1/7 uses Theorem). Every result followed by a prose intuition paragraph (7/7). **No proof anywhere in the body (7/7, absolute)**; proofs go to an appendix.
- One central mechanism, stated three times at rising formality: abstract, then introduction prose with zero notation, then propositions or tables.
- Objections named and dispatched in the body, in numbered subsections; an appendix does not discharge them.
- Magnitudes translated into economic units in prose.
- Roughly 8 tables and 7 figures if empirical. Theory papers substitute 5–7 figures and zero tables.

**Idiosyncratic, so choose deliberately and do not assume:**
- **Having a model at all: 8/14 yes, 6/14 no.** A prior claim in version 1 of this workflow that JFE requires model-first structure was wrong on both halves and is retracted here.
- **Model before empirics, among papers with both: 1 of 3.** Huang, Ranaldo, Schrimpf and Somogyi state theirs is "a static partial equilibrium model that rationalises the two main empirical findings from the previous section." Facts first, model as rationalisation, is at least as safe.
- **Causal identification of any kind: 3 of 9 empirical papers.** 6 of 9 make no causal claim, two saying so in the text. Only 2/14 use a natural experiment as the identification spine. What substitutes, in every one of the six: **a data moat plus an obsessive validation apparatus.** Graham et al. spend the whole second half of the paper defending the data source.
- Length 20–45 typeset pages, median 23; roughly 45–60 manuscript pages.

**The strategic reading.** The distribution is bimodal: 5 pure theory, 6 pure empirics with no formal theory, only 3 doing both. Attempting both is the minority strategy. **This paper takes the pure-empirics lane**, because a model added to reach for respectability would be the third-least-common configuration in the sample. Caveat recorded from the independent review: counting structural features across 14 papers describes what published papers look like and does not establish what caused acceptance, so this is a presentation-architecture decision and carries no claim about acceptance odds. A model is added later only if a specific empirical coefficient or threshold cannot be explained without one.

**Craft pattern to adopt deliberately: the named rival mechanism run as a horse race.** This is what no-model empirical JFE papers use in place of formal hypotheses. Bolton and Kacperczyk italicise three competing hypotheses in the introduction, use them as running labels structuring the results, and reject one of their own.

## 2. What the data actually supports (node C, partially measured)

The repo's real asset, and the thing version 1 failed to use: `data/unified/`, **2,277 daily parquet files, 2020-02-11 to 2026-06-30, roughly 215k swap legs per day, all eight venues** (uniswap v1–v4, sushiswap v2/v3, curve, balancer, fluid). It carries `tx_hash`, `component_id`, `n_components`, `route_class`, `tin_role`, and `tout_role`, so route components can be reconstructed across venues inside a transaction. Multi-leg is not synonymous with intermediated: directed token flow must still distinguish a sequential intermediary path from direct pool splitting.

Measured on all 2,277 days after enforcing clean routes and canonical endpoint identity: among true intermediary routes, the cross-venue count share rises from **2.0% in 2020 to 57.2% in 2026**, and the strict-support value share from **10.8% to 79.1%**. True intermediation nevertheless falls from **13.8% of economic routes in 2022 to 11.8% in 2026**, while direct splitting falls from **5.4% to 1.9%**; the horizon-balanced daily intermediation change is -2.03 points (SE 0.39, p<0.001). Complexity rises: routes above two legs reach **28.5%**, mean legs **2.58**, and mean venues **1.67** in 2026. A balanced five-venue perimeter retains a 2022-to-2026 cross-venue count rise from **21.3% to 44.0%**, but strict-support value falls **41.7% to 34.5%**, true intermediation **13.8% to 8.4%**, and direct splitting **5.4% to 1.4%**. Balanced coverage falls to 71.9%, and entrant-touching incidence is 20.4%, making the -5.35-point daily change a support-exit decomposition. Studying one venue in isolation becomes progressively wrong, but integration, direct splitting, true intermediation and route complexity are distinct margins; none identifies aggregator causality or better conditional execution.

The routing-efficiency attack separates four margins. Integration is the cross-venue series above. Within-vehicle search compares an exact two-leg realised route with the frontier through the same intermediary, retaining a comparison only when every frontier venue lies inside the route's observed venue set. Path selection expands that frontier to direct and alternative-vehicle paths. Vehicle rotation remains the realised intermediary-share result. The first margin is descriptive, the next two are conservative observed-venue-reach diagnostics, and none becomes a finding until the chosen pool sequence and counterfactual frontier are repriced at the same state and exact realised size. The preliminary grid matcher now carries the winning pool identities and refuses to blend quote-size endpoints when the intermediary, venue sequence or pool sequence changes. A 2022 smoke test shows why same-state is binding: the hourly matcher reports negative shortfalls on 63.2% of within-vehicle matches and 62.7% of best-path matches, which is timing contamination rather than a router beating its feasible frontier. The market-maturation test first estimates validated search, reach and path shortfalls within fixed ordered-endpoint, vehicle-address, sorted-observed-venue-set and fixed-notional-bin cells. D3 aggregates routes to equal-weight cell-days before F estimates the 2021-2025 calendar-year profile with cell fixed effects and two-way cell/date clustering. The 2025-minus-2021 contrast and joint year test are primary; a linear slope is only a summary, because maturation need not be monotone. Date fixed effects are forbidden in that profile because they absorb the object being measured; they remain appropriate for a separate within-date candidate comparison. The primary recurrent panel requires at least 10 observed days in each full year, with 30 as the strict support sensitivity. The three regret components are never collapsed before reporting, the primary outcome is the share above one basis point, and log-one-plus mean regret is a tail-sensitive alternative. Route-count weighting is an exact frequency-weight sensitivity: absorption, coefficient and cluster scores, and the CR1 residual degrees-of-freedom correction reproduce literal route-row expansion. The conditioned transition then asks whether the 2024-to-2026 stable rotation survives fixed endpoint-reach-notional opportunity regimes and predeclared bins of all three regret components. It retains only opportunity cells observed in both endpoint years, and the support ledger separately reports candidate and identifying cells and routes so cells present in one year cannot identify nuisance controls or inflate the stated sample. Its route-weighted primary uses the same frequency-weight correction, while equal-date weighting remains analytic and gives each date one unit of total weight. Exact 1-, 7-, 30- and 120-calendar-day cell links describe persistence only; missing target dates are not filled and rows are never shifted. Before any fit, horizon-by-origin-year support must agree with outcome completeness and returns to E-to-D review if any origin year retains below half its links or fewer than half the observed links of the best-supported year at that horizon. Aggregator attribution is conditional on executor and quote-authorship coverage; calendar improvement alone is named market routing maturation. All support gates execute before any trend regression. The run writes only its support ledgers and returns to E-to-D review if any full year's recurrent cell-day count or route count is below half of the largest 2021-2025 year; if fewer than half of transition candidate cells or routes survive common-opportunity restriction; if either transition endpoint year carries fewer than half the restricted observations or routes of the other; or if an exact horizon fails its annual link-support gate. It writes no coefficient or fitted specification while any gate is red. The routing estimators also fail closed when a required coefficient has a non-finite or nonpositive variance, and a joint Wald test requires a finite positive-definite restriction covariance; the shared regression primitive reports a negative covariance diagonal as missing instead of converting it to a zero standard error. If E later admits a flagged survivor design for diagnostic use, that admission is recorded as a lock deviation before the fit runs.

The V3 triangle-gap series is a separate price-integration diagnostic, not a router-efficiency outcome. Its recurrent panel says what happens within triangles observed at least a stated number of times; its horizon-balanced panel further requires the same triangle identity in every quarter of the sample span. Calling the first panel fixed support was incorrect because its observations could all fall in one short subperiod. Inference clusters opportunity snapshots by sampled date and applies a Bartlett HAC correction across ordered date clusters. Even the horizon-balanced trend remains descriptive: it can reflect arbitrage technology and triangle lifecycle, and aggregator attribution requires executor or quote-authorship coverage.

An independent review (2026-08-05) correctly demolished the version-1 reading of this as a "data moat". That is a weaker claim and gets stated as the weaker claim, and it does not substitute for identification. **The silo that was removed:** the old candidate-capital exhibit parsed Uniswap V3 provider files locally and called the result liquidity. Capital, local marginal depth, executable band depth and quote quality remain separate quantities; extending one requires its own family-specific contract and cannot happen inside an estimator.

## 3. Definitions to settle first (node C, blocking)

**Vehicle status and dominance are separate axes.** Vehicle status is a role that is binary and trivially satisfied: one bridging swap qualifies. What matters and what we measure is the *extent* to which one asset captures that role. The literature uses "vehicle currency" as a categorical label for what is really a continuous share, and making that precise is part of the contribution. Working title, a one-word insertion into the original public title so the public record stays continuous: **"The Making of Dominant Vehicle Currencies: Evidence from DeFi"** (decided by Java, 2026-08-06).

**Asset types before tickers.** DeFi is the laboratory and the claim is about currency types, so tickers appear only as proxies:
- *Native platform asset*: the platform's own settlement asset, classified independently of its pairing degree, volume, depth, route cost or volatility. Proxy: WETH. TradFi analogue: the incumbent international currency whose role may rest on thick-market externalities.
- *Stable numéraire*: low volatility, unit of account. Proxies: USDC, USDT, DAI. TradFi analogue: the managed or pegged stable unit.
- *Imported store of value*: non-native, wrapped. Proxy: WBTC. TradFi analogue: gold or a foreign reserve asset.

The general question is then venue- and coin-independent: does the vehicle role stay with the platform-native incumbent or migrate to the low-volatility numéraire, and what triggers migration? Pairing degree, volume, depth and cost are candidate explanations, never definitional inputs. That is the FX dominance-transition question, and we can observe the road not taken where FX cannot.

**Definitions belong on a slide and in a numbered subsection**, stated explicitly.

**What the route-cost experiment measures, stated once so it stops drifting.** For one trade, meaning a specific token pair at a specific hour at a specific size, the panel computes the best ONE-HOP route, which is the direct pool joining the endpoints priced at its cheapest venue, and the best TWO-HOP route through each candidate vehicle, where each leg independently picks its own cheapest pool across every available venue. It then asks whether routing through the native asset costs less than routing through the stable numéraire or the imported asset. Legs genuinely do cross venues: 32.3% of two-hop routes in the current panel have their two legs on different DEXes.

**Why this object and not realised swaps.** Vehicle-currency theory says the incumbent retains the role because routing through it is cheaper, which is the thick-market externality. The test is therefore the cost of the road not taken. FX data cannot run it, because the quote for the route nobody took is never observed; on-chain the state can be reconstructed and the counterfactual priced exactly, which is this paper's actual edge over the FX literature. What the panel does NOT measure is router behaviour or revealed preference. It is the cost surface a router faced, not the choices it made, and those are different papers.

**Consequence for venue coverage, which follows from the definition rather than from tidiness.** "Best available route" is defined over all venues, so truncating the venue set understates the best route on every leg and the bias direction depends on which routes lose most. Curve carries roughly 85% of Uniswap v2's volume on sampled 2024 days and sits where stable-to-stable legs happen, so omitting it plausibly penalises stable-vehicle routes hardest and flatters the native asset in exactly the comparison the headline rests on. Venue completeness is therefore part of identification here, not a robustness appendix.

**Balancer's coverage bound, signed (2026-08-06).** Balancer is the sixth venue and its weighted pools now price exactly: `ddvc.pricing.weighted` reproduces realised swaps at 0.0000% median absolute error with 100% of quotes inside 1%, scored on trades no fit ever saw, across twelve days spanning 2021-04 to 2026-02. Two things had to be identified from data before that held. The daily `poolSnapshots.amounts` record is the balance after the day's LAST event, so netting the day's flow off it and replaying forward gives per-swap balances; the two rival readings of that field score 1.7% and 2.8% on the same trades. And the flow has to include joins and exits, because a swap-only walk charges every liquidity event to the invariant and drops coverage from 87 of 105 testable pool-days to 177 of 367. The bound that remains is real and it is large: 256 of 473 testable pool-days price, and the excluded pools carry a median 91.8% of tested swap volume. The exclusions are decided by achieved fit error and not by pool type, and reading the types afterwards says what they are, namely the boosted and linear families and composable-stable pools.

**Correction to the line above, checked against the live schema (2026-08-06).** An earlier version of this paragraph said those families run StableSwap and could therefore be routed through `ddvc.pricing.stableswap` with Balancer's own `Pool.amp`. That is wrong for the two largest of them and understates the work for the rest. AaveLinear and ERC4626Linear, which carry a median 58.8% and 63.7% of a day's swap volume in the exclusion ranking, are not StableSwap at all: they hold `lowerTarget`, `upperTarget`, `mainIndex` and `wrappedIndex` and price a wrapped position piecewise with different fee treatment inside and outside the target band, so they need their own module. The binding obstacle is rate providers: `priceRate` is not one, reading 1.2397 for wstETH and 7.76e-10 for a boosted-USDC token, balances must be scaled by it before the invariant, it is absent from the extended schema, and it drifts continuously so a head-block reading cannot serve a past day. The linear and boosted families stay out until a linear module exists. ### 4.0 What is taken, what is open, and where incumbency can legitimately live

Two independent cross-family reviews plus a four-lane prior-art sweep settled this section. Revised 2026-08-05. The earlier version was wrong in three ways, retracted here explicitly.

**A realised route does not reveal trader habit.** Conditional on a router's information, objective and integrated opportunity set, its optimisation can mechanically select the currently cheapest route, so an incumbent intermediary appearing when a reconstructed direct route is cheaper does not by itself identify trader inertia. The apparent mistake may instead reflect stale state, gas, private liquidity, MEV protection, a restricted venue set or a software default. Version 1's plan to read a wrong-signed cost coefficient directly as Krugman/Eichengreen inertia is retracted. Persistence can still reside in the routing system's slowly updated opportunity set or objective, which must be measured as institutional state instead of assigned to traders.

**Adjacent work exists and must be cited.** Xi and Moallemi (2026) audit 2.98 million WETH-USDC swaps, comparing realised routes with support-constrained, full-venue and gas-aware full-venue optima; their paper is forthcoming in the Financial Cryptography 2026 workshop proceedings. It reports a 2.02-basis-point mean shortfall and $24 million aggregate, identifies failure to activate additional pools as the dominant loss margin even after gas, and shows that state staleness materially enlarges measured shortfall. Their scope is parallel allocation across pools for one endpoint pair on Ethereum L1 and explicitly excludes intermediate tokens and multi-hop routing. That boundary preserves this project's vehicle-currency question, but it does not erase the methodological overlap. Citation duty follows intellectual proximity, not venue rank or the citation frequency of a JFE exemplar set. The paper must cite Xi and Moallemi, concede that realised-versus-optimal routing audits and the support-versus-public-opportunity decomposition are prior art, and establish every empirical object it uses from its own data. Our contribution begins at sequential intermediary choice, vehicle-linked liquidity and long-run vehicle formation, rotation, or persistent replacement after routing maturation is held fixed.

**The entry contract does not identify the aggregator.** The earlier text asserted it did, which contradicted `docs/router-identification-feasibility.md` in this same repo. Corrected: `sender` identifies the **executor**, because Universal Router executes calldata computed off-chain and any wallet or meta-aggregator can call it. The executor population fragments to 397 distinct senders by late 2025 with a hand registry capturing 11.8% of swaps. Maury (Zenodo 21513263) argues no standard on-chain mechanism announces frontend identity and supplies four recovery heuristics; Xi and Moallemi's own labelling reaches roughly 21% of transactions and 5.6% of volume on a single pair. Any executor attribution must be built by trace classification with an address-version registry, and stated as partial.

**What is genuinely open.** The intermediary-asset margin, multi-hop routing, and matched-trade head-to-head comparison are unoccupied. Separately, **nothing in the literature connects DEX routing to the vehicle-currency question at all**: searches for vehicle currency plus DeFi routing return zero. The framing is the contribution, and the multi-hop intermediary margin is promoted from incidental to central.

**Where incumbency can live.** Stickiness can reside in (i) **LP capital allocation**, since providers face switching costs, gas costs and attention limits, and (ii) **routing-system scope and defaults**, business and software decisions updated on a slower cadence than individual quotes. A router choosing the native asset because its pools are deepest may be mechanically optimal at that instant, while the reason those pools are deepest may be historical incumbency. Likewise, a restricted venue set or default path can persist even when the inner optimiser is deterministic. These are state variables to measure, not evidence of trader habit at quote time.

**Structural breaks are the identification spine.** This is the most consequential correction. The FX literature's decisive gap is that an incumbent's cost advantage is itself a consequence of its incumbency, so the data never contain the state in which a currency holds the vehicle role while being strictly cost-dominated by a rival. Gas-regime shifts, fee-tier introductions, protocol-version migrations and the March 2023 depeg are candidate windows in which exactly that state occurs on-chain. Earlier drafts listed these as regime controls to absorb. They are the variation to exploit.

**Condition retested 2026-08-07, and the level state exists on bounded support.** See `docs/finding-cost-dominance-measured.md`. The failed daily-median test remains retired because intraday price movement swamped execution cost. The replacement uses strict pre-transaction V2-family state, exact realised input, historical gas prices and receipt-calibrated route gas. Among 45,720 comparable legacy routes on 73 nonempty dates from the fixed 74-month calendar, direct returns more gross of gas on 11.7% and costs less all-in on 31.1%, with a matched-cell IQR range of 24.8% to 35.8%. This establishes that realised vehicle routing can coexist with a cheaper direct path. It does not resolve persistence or inertia: support collapses late, the perimeter omits modern venues, and a pair-candidate-period persistence estimator remains open.

**On mechanical results, per Java: keep them, demote them.** Architectural factors (pair availability, pool existence, netting) shape dominance and belong in the paper as the layer that sets the feasible set, with slower allocative choices selecting within it. They may not lead, because a result whose sign is guaranteed by construction fails as a contribution.

### 4.2 Measurement requirements

Non-negotiable, because getting these wrong invalidates everything above. Adopt named methodology, which also buys referee familiarity.

- **Route cost: build a three-benchmark ladder ourselves.** The construction is standard optimisation and nobody's proprietary contribution, and Angeris, Chitra, Evans and Boyd (published) supply the theoretical warrant that gas-aware optimal routing is mixed-integer convex, so production routers are necessarily heuristic and a measurable shortfall exists. Suboptimality as proportional shortfall of the realised route against benchmarks solved at fixed pool state: support-constrained (reoptimise splits only across pools the trade touched, isolating mis-splitting), full-venue (reoptimise across all pools without gas, adding venue omission), and gas-aware full-venue (fixed per-pool activation cost, mixed-integer). Use a direction-asymmetric gas model, since one swap direction deducts from output while the other shrinks the input budget. Report medians alongside means, because a few per cent of trades drive the entire mean.
- **Cost level: adopt Barbon and Ranaldo's definition** of total cost as slippage plus fee plus gas over notional, on hypothetical trades at a fixed notional grid, hourly, with gas as a unit count times median gas price. Their headline: validator gas dominates trader cost, ahead of classical price impact.
- **Separate incidence, route-quality magnitude and economic-loss magnitude.** Dominance incidence and route-quality improvement compare two quantities of the same output token and therefore require no external token-price estimate. The price-free ratio is primary on the full route universe. Economic loss still converts both outputs to one value unit and divides their difference by input notional, but only on explicit input/output valuation-coherence support. Thin-token daily marks can value realised output at tens or hundreds of times marked input and manufacture enormous input-normalised basis-point magnitudes without changing which route returns more. Every incidence estimator must export the representative dollar magnitude, aggregate on admissible support, concentration in the upper tail, and a size distribution from the same sample. A frequent $8 friction and a rare $8,000 loss are different findings even when their incidence matches. Report each object under its own name; none substitutes for another.
- **Depth: realised all-in cost at fixed notionals is primary; marginal-price displacement is a secondary structural descriptor.** The earlier plan to define depth as dollars to move the marginal price 10 and 50 bps then "aggregate" across venues was wrong twice over. Marginal-price displacement and realised average execution cost stand in a design-dependent relation (roughly a factor of two in constant product for small trades, different entirely for stableswap's flat-then-convex curve and for concentrated liquidity's tick-dependent piecewise shape, where large marginal depth can coexist with a costly range exit). And the economically correct aggregation across heterogeneous pools is the joint split optimisation, and a sum of per-venue depth numbers has no economic meaning. There is no accepted academic depth standard; our own SoK (Xu, Paruch, Cousaert and Feng, ACM CSUR) is the natural citation for design-specific slippage and is checkable locally since we are an author.
- **Gas units and gas prices have separate owners.** A two-hop vehicle route is mechanically more gas-expensive than one hop, so omitting gas biases the comparison toward the vehicle route and makes direct-dominance incidence a lower bound. Route units come from a deterministic receipt sample conditioned on topology, venue sequence, year and intermediary type; transaction-level medians and interquartile ranges are primary because router bookkeeping remains inside receipt gas. Daily gas price comes from every transaction in three evenly spaced full blocks, with V1 then V2 then V3 supplying only the block calendar. The rejected first implementation used the first 500 V3 swaps after midnight and repeated the gas price of multi-swap transactions, so it neither spanned the day nor weighted transactions once. Empty-but-successful historical-block responses trigger endpoint rotation, fewer than two resolved blocks fail the day, and any unresolved day prevents the panel from being written. Cache only completed day summaries and write them atomically. The completed build covers all 2,277 project days with zero unresolved dates, 2,258 three-block days, 19 two-block days and median support of 590 transactions per day. Analytic-panel column order is declared explicitly because concurrent completion order must not alter a first-run Parquet schema.
- **Separate MEV from routing shortfall.** Realised amounts embed sandwich losses while simulated counterfactuals do not, so flag sandwiched trades and report cost both ways. Do not condition naively on submission channel: a large share of sandwich victims migrate to private RPC within weeks, which makes channel an endogenously selected treatment and disqualifies it as a control.
- **Intent venues need separate treatment.** Batch-auction and RFQ settlements may be internalised against solver inventory, in which case no AMM counterfactual describes the user's alternative. Treat batch venues as a structurally different cost regime, and do not assume solver competition passes value through, since more solver entry can reduce welfare.
- **Symmetric split treatment.** Comparing an unsplit best-single-pool direct route against a realised split vehicle route is not like-for-like.
- **Transaction-time state.** Transactions earlier in a block move reserves and ticks; report the wedge if daily state is used anywhere.
- **Sign the venue exclusions.** Under full-venue logic an omitted venue mechanically flatters whichever route depends on covered venues, so state the direction of the bias as well as its share.
- **Endogeneity, answered where it can be.** Whether an asset becomes the vehicle because costs are low or costs are low because vehicle liquidity accumulated is answered by cost-dominance windows and cross-venue spillover. The cross-aggregator cross-section cannot answer it, since a snapshot of routers contains no variation in incumbency holding cost fixed.
- **Self-returning, wash and arbitrage screens before any regression.** Canonical endpoint round-trip exclusion is already implemented and mandatory because those routes are outside the endpoint-conversion unit: they run 12.7% of multi-leg routes by count and 21.7% by value on the median of 79 sampled days, reaching 25.9% and 91.3% on 2025-12-06, the worst. This operational rule does not classify every excluded route as wash trading or arbitrage. The turnover-spike and volume-spike screens, explicit arbitrage-cycle detection and organic-versus-MEV decomposition in the reference repo's `ddc.integrity` still need applying separately.

**First check under the accuracy framing found a real error, 2026-08-06.** The load-bearing LVR closed form in equation `eq:lvr` was cited to `MilionisMoallemiRoughgarden2023Myersonian`, "A Myersonian Framework for Optimal Liquidity Provision in Automated Market Makers". The result actually comes from Milionis, Moallemi, Roughgarden and Zhang, "Automated Market Making and Loss-Versus-Rebalancing" (arXiv 2208.06046), a different paper with the same three lead authors, which is exactly why it was confusable. Corrected in `05-liquidity.tex` and in the provenance comment in `05-rivals.tex`, with the correct entry added to the bib.

The formula itself is right: instantaneous LVR of one eighth of the variance rate times pool value is standard for the constant-product invariant. So the rent-incidence result stands unchanged and only the attribution was wrong. That is the good case, and it is worth noticing how much rested on it: `eq:lvr`, `eq:lvrrate`, the -5.96% median net yield, and the arithmetic rejection of the centrality curse, which turns on LVR as a share of capital carrying no depth term.

The lesson generalises. The exposure was never that somebody else had reached the result first; it was that the paper said something false about a source it leans on, in a paper whose whole substitute for identification is a validation apparatus. Check what we assert about what we cite, especially where several papers share authors.

Independence is the point. Form the reading from our own measurement, then check the sources we lean on.

**Parallel literature work is paper-grained.** Independent paper families may be discovered, downloaded and audited concurrently. One owner keeps a paper's published article, appendices, supplements, corrections, replication artifacts, full reading and claim adjudication in one sequential chain because companion evidence can reverse the main text's apparent result. Workers use isolated staging directories and manifests and do not edit the shared ledger. One reconciler verifies versions and hashes, removes superseded artifacts, writes the source-set record and closes the card. Never split one paper across concurrent readers merely to increase throughput.

**The literature gate binds evidence to the live manuscript.** `literature/use-contracts.json` is the single executable registry for adjudicated citation-use boundaries and vocabulary rules; `scripts/audit_findings_freeze.py` is the sole gate owner. Each claim-use rule points to the evidence-card field that establishes the boundary, then checks only paragraphs that cite that source. This is a deterministic guard against known semantic conflicts, not an automated substitute for reading: a newly discovered conflict becomes a reviewed contract before the card closes. Vocabulary absence has a different rule from methodology. A configured term is barred when it appears in the manuscript, appears in zero documents across the declared finance/economics corpus and the coverage floor passes. The absence of a method or measure never bars it; only an explicit source prohibition can do that. Main and companion extracts are search aids, not source artifacts. Every required PDF must be locally present and match the tracked checksum. An unavailable appendix keeps the source set and any card calling it complete open, while an explicitly embedded appendix closes only through the checksum-verified main PDF.

## 5. Method discipline adopted from documented practice (node F)

Sourced from an R&D pass over reproducibility and specification-robustness practice; full sourcing in the agent output.

- **Delete-and-rebuild as the gate** (Gentzkow and Shapiro). A run is done when a fresh clone regenerates every number, table and figure with no manual steps. That is the definition of done.
- **Machine-readable decision registry.** Every analytical choice is declared as a named parameter with alternatives enumerated in `docs/specification-lock.json`. The lock hashes its canonical content and the findings audit recomputes the hash, rejects duplicate claim IDs, and requires every entered claim to state its dependent variable, transformation, outlier rule, inference, alternatives, falsifier, interpretation bounds, inputs and outputs. Mitton (RFS 2022) showed that with discretion over ten routine choices a researcher can report over 70% of *randomly generated* variables as significant determinants of leverage; the three choices that matter most are dependent variable, transformation, and outlier treatment, so those are mandatory-to-vary.
- **Specification curve per headline claim** (Simonsohn, Simmons and Nelson), with the dashboard showing which choices drive the result and a joint inference test. Curated to reasonable specifications; a padded combinatorial multiverse deflates visible dispersion.
- **Multi-agent replication as a bug detector only.** Demoted after the independent review, correctly: Menkveld et al.'s 164 human teams measured genuine researcher variation, whereas N LLM agents on one codebase measure code-generation noise. Presenting that to a journal as an econometric quantity would be process theatre. Retained internal use: run the estimate independently twice with separate contexts, and treat any disagreement as evidence that one run has a bug. Menkveld et al.'s finding that dispersion falls after peer feedback still justifies putting the critique round before estimates are fixed.
- **Specification lock plus deviation log**, replacing external pre-registration, and placed **after** an explicit exploratory phase. The review objected to the friction; the exploratory-first ordering answers that, since distributions, pool anomalies, and contract mechanics must be understood before specifications are fixed. Burlig (2018) shows PAPs carry no epistemic credit for archival data, so this claims none: it is an internal integrity device, needed because version 1 did silently reframe results after seeing them. Keep the audit trail, decline the binding commitment.
- **Report everything run** (Harvey, JF 2017). Every specification goes to an internal appendix; the drafting agent may not silently select.
- **Time means calendar time after support balancing.** A HAC estimator over filtered observations must receive the actual date index. Unsupported gaps contribute no autocovariance pair; the row after June 30 is not treated as one day away from January 1 merely because July through December were removed. Every balanced endpoint-year exhibit records this contract in its output.
- **One economic choice gets one primary vote.** When path complexity changes over time, counting every intermediary occurrence gives a longer route several votes. The primary vehicle-choice estimand therefore uses exact two-leg routes with one intermediary; all intermediary episodes measure network extent and remain a prespecified extension.
- **Desk-reject filter, early.** JoF desk-rejects 43% before review. Before any polishing, one agent answers: what is the single novel contribution, and is it visibly large enough in the first two pages? A negative kills or reframes.
- **Rank-ordered internal referee** (Berk, Harvey and Hirshleifer): output must separate fatal from major from minor, every objection carrying a scientific argument. Undifferentiated flaw lists are penalised, since that is the failure mode LLM reviewers default to and the exact pathology the paper warns human referees against.

## 7. Gates on every deliverable

- **Language, and it stays a real gate.** Run the repo-native conformance scripts through `scripts/run`; they resolve the 14 published JFE exemplars from `literature/pdf-sources.json`, with no scratch-directory dependency. Three layers: pattern metrics calibrated leave-one-out against the 14 papers, n-grams absent from the whole corpus, and log-odds over style vocabulary. Catalogue encoded from Wikipedia:Signs_of_AI_writing. Measured baseline for my own prose: em-dashes ran 10x the corpus maximum against a corpus median of zero, and "X, not Y" ran 39x the maximum.

  The independent review called this cargo-culting on the grounds that referees reject for weak identification and never for punctuation. **Java overrules that, and the argument is availability bias.** Before generative models, em-dash density was not a signal about anything, so nobody rejected on it. In 2026 a manuscript that reads as machine-written raises a referee's eyebrow about everything else in it, including whether the analysis was done carefully. The prose is evidence about the author's care, so the gate stays binding. Two guards against the review's legitimate worry: the gate may never be satisfied by convoluted phrasing (a flagged sentence gets rewritten simpler), and it never outranks substance in review priority. It also supplements and does not replace the house-voice blocklist, since roughly half those rules are voice and not venue anomaly.
- **Prose shape, the positive gate.** `./scripts/run scripts/measure_venue_shape.py [--section NN]`. Reports the venue's interquartile band for each shape target beside the draft. Binding alongside the two subtractive gates, never instead of them. Aim at the band, never at zero, and never satisfy it by convoluted phrasing.

- **Deck craft.** Load `slide-deck-authoring` and `diagram-design` before authoring; failing to do so last time produced 17 tables against one image. Data-overview slide mandatory. Every result a plot or diagram first, table only in backup. Phrases and short clauses, never full sentences, on core and backup slides alike. Inline citations throughout, plus a references slide. p-values as bare parentheses, `(0.003)`, and `(0.000)` below 0.001. No TODO frames ship.
- **Reproducibility.** Delete outputs, rebuild from one script, byte-compare. Pinned manifest, RNG seeds, execution order, auto-generated README.
- **Cleanup.** Superseded artefacts are deleted in the same commit, but only after the replacement has a current provenance verdict and a repository-wide consumer search finds no live reader of the old path. Run that search as a separate fail-closed step: every match must be classified before deletion, and a best-effort search must never share a shell invocation with the destructive command. Delete the artefact and its provenance stamp together. A stale artefact with a live consumer is not a duplicate: rebuild it or retire the consumer, and keep it blocked from claims until then. Worktree outputs remain isolated even when two branches happen to produce identical bytes; immutable generation-keyed caches may be shared through the Git common directory. After a generation-keyed replacement is green, compute the live key from current code and inputs, verify that no active process owns an older key, and retain only the live generation. The registered-input audit and the paper build both fail while any required artefact is stale or missing.
- **Caches are resumability state, not scientific inputs.** An assembled artefact's provenance points to canonical source inputs and code, never to its generation-keyed day cache. Record the cache generation in notes, validate every shard during atomic assembly, then allow the cache to be deleted after the assembled replacement is current and no process owns it. A cache may accelerate reconstruction but cannot be required to keep an otherwise complete release current.
- **A state cut is part of the estimand, and a shard needs a completion certificate.** Preserve canonical block-log order until the named cut is applied. An end-of-UTC-hour grid applies every event before the next hour and remains a descriptive hourly surface; a transaction frontier applies only events strictly before the target block-log and is a separate object. Both use one ordered cursor, never split liquidity and swaps into type buckets. A cached shard is reusable only through a marker written after the parquet and binding the full code/input generation, resolved scientific scope, cut semantics, relevant state-quality fingerprints, date/hour bounds, schema, row count, content hash and economic-key hash. Assembly first publishes one ordered manifest over all verified shard markers. A bare parquet, a missing or edited marker, a mutated shard, mixed generations or an existence-only legacy cache is rebuilt, never migrated into the current release.

   **LEAD: the intermediation transition.** It measures realised routing, and the corrected topology/value contract survives its sharpest observed-composition attacks.
